# 四项高差距工作负载的架构优化路线

状态：2026-11-15用户要求转向架构级优化；本文为实施合同。G首切字段驻留状态机已默认落地；其余架构切片待实施。
本路线初始产品基线45bfabda，既有结果见[aot-hotspot-dispatch-optimization.md](aot-hotspot-dispatch-optimization.md)。

## 判断与共同基础

generators、comprehensions、records和list_ops继续作为固定原始输入，不改算法、规模或入口。
后续重点是减少对象物化、状态搬运和动态边界，而非继续以Runtime分派细节作为主线。

源码事实：

- 普通生成器由`generators.rs`降级为工厂和恢复函数。除只读形参省写外，每次挂起保存全部局部，
  每次恢复加载全部局部；控制槽和状态都在object[]中。暂停点活跃性旧实验未取得收益验收，
  新架构独立设计，不恢复该实验作为依赖。
- 推导式是独立嵌套函数，私有list收集器已直调，但迭代值、算术和结果构造仍有动态边界。
- PyInstance已经使用类槽位与object[]属性数组，构造器按当前槽数预分配。records的方向是
  布局/方法专门化和聚合临时值消除，不能按“每个实例都是字典”制定改造。
- 普通PyList使用List<object?>，另有数值与bool背板。精确extend已使用AddRange；
  大列表还涉及装箱、连续数组扩容复制、旧数组的GC高水位及通用读写。

四项共用“有守卫的类型化执行区”：MIR证明值来源、类型、别名和效果，在区内使用原生标量、
稳定字段或存储视图；在可观察边界物化正确Python对象。codegen只翻译MIR显式事实，
不增加HIR依赖，不从函数名或基准名字识别算法。

## 必须先建立的编译器合同

1. 统一循环区摘要、定义使用链、支配与活跃性分析，记录常量范围、精确类型和存储版本。
   分析结果随CFG/定义变更失效；遍历有预算，输入不支持时返回正常通用路径。
2. 效果分类区分精确运算、分配、容器写、用户协议、异常、暂停和反射观察。
   每种MIR语句/终结符必须显式登记读取、写入及观察性质，避免遗漏无名临时槽。
3. 为每个边界定义物化映射：逻辑局部、原盒身份、别名、当前行号与已提交副作用。
   入口守卫失败可回原入口；区内溢出或失效必须从当前操作继续，禁止重放已完成写入或回调。
4. Python整数溢出升级、已有对象身份和跨桥同步属于正常合同。新鲜未逃逸值可以延迟装箱；
   已存在的盒必须保留原引用。资源耗尽时点若改变，单独ADR登记。

## G：生成器状态机与消费融合

进展：字段驻留首切已通过完整门禁、CP/JIT/NativeAOT删除输入搬迁、NumPy和原始26项。
生成器完整原程序全量耗时-22.23%，重点10轮-26.29%；分配与RSS基本持平。
实现边界及下一步见[验收记录](aot-generator-state-optimization.md)。

首切用编译器生成的状态机载体替换全局部object[]搬运：PC采用原生整数，长期局部直接驻留
字段，短命临时只存在于本次恢复调用；每个恢复入口有显式live-in与异常边证明。
先建立状态机表示，再在证明整数范围后引入原生计数器，避免只把数组访问换成字段访问。

PyGenerator继续负责Python可见身份、running/closed、send/throw/close、PEP479、
异常上下文与真实调用帧。新旧状态机在创建前选择，暂停后迁移必须有明确状态映射。
EH、yield from、product trace逐项接入，首切不放宽现有拒绝门。

随后针对未逃逸的生成器消费者融合执行区：保留函数捕获与绑定身份、首次启动、逐项副作用和
提前终止清理，减少逐元素委托往返。单独验证普通for、sum和yield from，不能仅以sum获益
宣称整个generators完成。

## C：推导式的类型化循环与私有构造器

为合成推导式提供明确来源元数据，在独立作用域内形成类型化循环区，保留最左迭代器的
立即求值、过滤顺序、嵌套循环顺序、异常及闭包捕获。list/dict/set分别采用私有构造器，
容量仅由已证明的安全上界决定；输出内容与身份可观察前准确物化。

range产出的原生索引、算术中间值、enumerate的临时二元组和立即解包优先保持标量形式。
用户迭代器、可变列表、未知协议及保存到外部的值依照效果边界回退。不得把私有收集器
证明推广到普通用户容器，或将独立作用域扁平化而改变绑定与异常帧。

## R：固定布局对象与无分配聚合键探针

保留Record对象实体和可变别名。在精确类、类版本、描述符及实例遮蔽守卫成立的执行区中，
固定字段读取和已绑定方法正文专门化；未知用户调用作为失效边界。逃逸对象仍可由原通用
PyInstance访问，读写两条路径共享同一存储和物化状态。

聚合层将仅用于查找/更新的短tuple键保持为原生标量探针，只有真正插入或逃逸才构造tuple。
先限定精确字符串对和默认字典比较器，并证明字典当前键域不含可回调键；任何异构插入使
该证明失效。用户hash/eq可能观察查找键身份，必须沿真实tuple通用路径。
可借鉴既有PyLruStringPair的探针/实体分离，但不能直接套用其LRU键合同。

records按生成文本、解析对象、分组聚合、排序输出分别诊断，最终仍验收完整原程序。

## L：列表存储与批量访问

首先评估身份安全的分段引用背板，服务大规模append/extend，减少连续扩容复制及旧大数组
驻留。已有元素保留对象引用；精确self-extend固定初始长度；公开Items访问完整物化且永久
回到兼容背板。数值与bool背板分别处理，Count及matmul原热路必须单独保护。

再由类型化执行区为新鲜、未逃逸数值提供紧凑存储和原生索引。存储版本守卫、负下标、
越界、切片独立列表、迭代时增删、别名和桥接写回必须闭合。使用过的对象盒不能重新创建
以换取紧凑布局；布局变更与循环批量化分成独立可测切片。

## 推进顺序与验收

先做共同分析/物化合同，并以生成器状态机为首个架构竖切；随后推导式共享该类型化基础。
records与list_ops先完成分阶段诊断，再分别落布局/键探针和存储切片，避免四套不相容机制。
每个重大取舍独立ADR；未通过验收的候选不进入默认产品。

每个切片先手写pending和真实源结构断言，再进行同次CPython3.12.13差分、冻结旧新CLI的
独占NativeAOT配对、输入删除搬迁与NumPy边界保护。保留原26项作为副作用与性能保护，
最后make check。记录真实装箱/分配、每次恢复的数据搬运、主表墙钟与RSS，区分诊断轮和主表。

目标继续是四项逐一达到CPython速度和RSS，速度优先。计划不填预计倍数，不将减少IR指令数
当作收益验收。其他平台与JIT分别登记。本文只确认架构方向与准入，不宣称四项产品完成。

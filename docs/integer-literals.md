# 大整数字面量：有界编译期正规化

目标是解除固定 texttable 源码中 `12800000000000000000000` 的编译阻断，
保持十进制、十六进制、八进制、二进制、下划线与一元符号的整数精度。
这不是扩展浮点字面量，也不引入运行时 Python/第三方大整数解析器。

Ruff 当前 `Int` 使用 `Small(u64)` 或保存原 token 的 `Big`：
十进制已去下划线，超范围非十进制保留前缀/分隔符；`Display` 不是通用十进制转换。
小于等于 u64 的现有 HIR `Literal::Int` 快路保持不变。
更大的值经独立 helper 正规化为十进制 `Literal::BigInt`，类型为 Dynamic，
不启用基于 i64 的静态整数运算/快速幂假设。

正规化只接收 Ruff 已验证 token，不重复实现 Python 词法语法：
十进制流式去分隔符/前导零；2/8/16 进制用 base10^9 小端 limb 乘基数加一位。
每步精确检查有效十进制位数，超限返回结构化错误交 HIR 发 E0100，
无整型溢出、panic 或无界先构造再拒绝。每 limb 的乘积与进位使用 u64，
最大 radix 为16，limb严格小于10^9。

**本实现容量上限为 4300 个有效十进制数字**，不计前导零、下划线和独立一元符号。
该容量也约束非十进制字面量的正规值：不能把它表述成 CPython 对所有进制的限制，
CPython 默认十进制转换限制与二次幂进制的能力范围不同。
上限之外是明确未支持资源边界，不截断、不取模、不退回不精确 double。

复用 MIR `Constant::BigInt`、codegen 既有 BigInt 常量池与
`PyOps.FromDecimalString`，在程序集常量初始化时构造 Python 整数对象，
而不是每次执行字面量再解析文本。现有常量池身份/生命周期策略保持不变；
不是为 `is` 增加跨实现保证。已纠正此前未实际启用的 `boxed_const(BigInt)`
把已装箱动态值误当 i64 的分类，并以 MIR/CIL 验证锁定。

成本：大整数的正规化在编译期承担有界 O(输入位数 × limb数) 工作；
常量池保留大整数对象，启动时仍需十进制解析。小整数静态路径不增加检查或装箱，
不据此宣称整体程序加速。字典纯标量字面量识别也应接纳 BigInt，避免额外用户回调守卫。

已覆盖的验收：
- helper 单测：四进制同值、大小写、分隔符、前导零，4300/4301有效位；
  `2^14284` 与 `2^14285` 的精确容量边界；异常token返回错误不panic。
- HIR/driver：超u64旧拒绝案例迁为精确BigInt，超4300位四进制 E0100，
  不再残留64位/128位范围误导；小整数 typed MIR保持静态。
- 真实差分：精确值/算术/比较/负号/反码/移位/默认值身份/同值字典键；
  4300位正负字面量；固定 texttable 项目新首阻断统计。

## 参数默认值与静态优化边界

函数标注不是运行时强制转换。定义时计算的默认对象可能是 BigInteger、容器或其它
动态值，不能因 `value: int` 而在缺参调用时强制拆成 i64。
类型检查复用现有模块表达式提示，默认实际类型未知、为 Dynamic 或与标注不符时，
只将该函数降级为对象参数/返回值。整数默认值还需要 i64 范围证明：当前证明范围为
直接小整数字面量与可精确检查的一元正负/反码链；整数算术、调用及模块变量等未证明
范围的默认值保守降级，不能仅因提示为 Int 就假设不会产生大整数。
嵌套定义的默认值属于外层表达式 arena，有默认值的嵌套函数保守走动态路径。

这会放弃部分本来可优化的默认值函数，例如 `value: int = 1 + 2`，是当前正确性优先
的保守边界，不宣称默认值函数性能无变化。无默认值的小整数函数，以及有直接安全
小整数默认值的函数仍可保持原静态路径；不主动把所有函数或整个模块强制降级。
类型检查规则不改变默认值的实际执行位置、次数或返回对象身份。

## 当前测试与项目结论

- `integer_literal` 单元测试覆盖有界正规化；`integer_literals` driver 测试覆盖
  四进制容量诊断、HIR/类型/MIR/CIL 与独立小整数函数静态签名。
- `m3_7_big_integer_literals.py` 的固定 CPython 3.12.13 差分包括巨大字面量、
  旧超 i64 值、一元表达式、`2 ** 100` 与 `int(string)` 的带标注默认值。
- `m3_7_integer_capacity.py` 验证 4300 位真实运行结果与负号显示长度。
- 固定 texttable 项目的大字面量编译阻断已解除；下一实际阻断是运行时缺少
  `unicodedata`，因此本切不把 texttable 统计为原生通过。

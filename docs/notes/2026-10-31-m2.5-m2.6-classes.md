# M2.5 / M2.6：普通 class、属性协议与自定义异常

## 做了什么

- **普通类不生成 CLR 类型**：`class` 被降级成模块入口里的一条运行时语句。MIR 先求值基类，
  调用 `PyOps.MakeClass`，再按源码顺序执行类体（属性赋值、方法对象创建、表达式副作用）。
  这样类体顺序、方法默认值求值时机和模块语句的相对顺序自然与 CPython 一致。
- **方法就是普通函数**：类体里的 `def` 在第一遍收集时分配 `FuncId`，运行时创建 `PyFunction`
  放进类属性字典。调用 `obj.m()` 由 `PyObject.GetAttr` 绑定接收者，再交给已有的 `CallValue`。
- **属性协议**：新增 `PyClass` / `PyInstance`。查找顺序是「数据描述符（property）→ 实例字典
  → 类链」。绑定方法记录定义类，零参数 `super()` 从线程局部的方法上下文取得 `(owner, self)`。
- **魔术方法**：`PyObject.TryMethod` 是统一入口，接入 `__repr__` / `__str__` / `__eq__` /
  `__hash__` / `__bool__` / `__len__` / `__iter__` / `__next__` / `__getitem__` / `__setitem__` /
  `__contains__` 与常用一元 / 二元运算槽。用户迭代器用 `PyInstanceIterator` 适配成
  `IPyIterator`，因此 `for` / `list()` / `in` 不需要知道对象是不是内建容器。
- **自定义异常**：codegen 为每个用户异常类生成一个 CLR 子类，并在模块初始化时写入
  工厂委托。运行时通过委托创建异常对象，CIL 的类型化 catch 因此仍然按 Python 继承树匹配。
  多级用户异常通过生成的基类构造函数转发。
- **身份**：普通对象与 `frozen=True` dataclass 都是引用类型；装箱、传参、放进容器只复制引用。
  `identity(point) is point` 这类用例已通过。

## 缓存与失效

`PyClass` 的属性查找缓存按「类 + 名字」保存结果，但条目记录**全局修改版本**。任何类属性
增删或替换都会递增版本，下一次查找自然失效；条目超过 256 条时整体清空。这样实现简单、
容量有界，也不会在「方法替换后还返回旧绑定」这类场景下出错（semantics.md 陷阱 #22）。

## 踩到的坑

### 1. 异常处理表：dotnetdll 的 fat section 写坏了小 clause

加入用户异常后，一个带 `try/finally` 的用例突然报 `InvalidProgramException`。`ilverify`
显示异常表目标越界。根因在 vendored `dotnetdll`：异常段如果因为某个子句而选择 **fat**
格式，循环里却调用 `Exception::TryIntoCtx`；后者会按单个子句能否压进 small 格式来决定写
11 字节还是 24 字节。结果同一个 fat section 里混入了 11 字节子句，后续 clause 全部错位。

修复：`Exception::TryIntoCtx` 只用于 fat section，始终写完整 24 字节；small section 仍由
`DataSection` 的写入路径逐字段处理。patch 保留在 `vendor/dotnetdll`，并在这里记录原因。

### 2. 实例方法的参数下标

生成用户异常构造函数时，最初把第一个形参写成 `ldarg.0`。实例方法的 `ldarg.0` 是 `this`，
参数从 1 开始；于是运行时把 `PyClass` 当成 `object[]` 传给了消息构造函数。用反射直接调用
生成类型构造器并打印 `Args` 才发现类型错位。修正为：1 = `PyClass`，2 = `args`，3 = `typeName`。

### 3. `raise SomeException`（不带括号）

`raise StopIteration` 的操作数是异常**类**而不是实例。`PrepareRaise` 现在会先把 `PyClass`
或内建异常 `PyType` 实例化，再走原来的异常检查。

## 还未做的

- 多重继承、元类、任意类装饰器、自定义 `__getattribute__` 明确报 `E0100`。
- `__init__` 返回值检查、`__new__`、描述符的完整 `__get__` / `__set__` / `__delete__` 协议仍未实现。
- 用户异常类只在单模块内工作；跨模块异常匹配要等 M2.7 的模块系统。

# M3.9 有界优化验证记录

状态：原五项有界验收完成；代码门禁、固定项目、整套性能及实际 JIT 证据已通过/归档，等待整里程碑发布。

## 范围与默认决定

保留原 M3.9 五条，不改变 16/20 的独立 M3.11 兼容门。M3.8 可选桥接仍未完成后排。
本次默认实现为有证明的临时 tuple 标量替换与有限区间拆箱；
直接累加槽、纯叶函数特化都有完整实现/正确性/配对证据，但失败或通用场景有回退，
因此只通过独立显式实验开关启用，不冒称默认提速。具体证明与取舍见 ADR-0033 至 0036。

- TupleScalar：同块新鲜匿名 tuple，至多 8 元素/每函数 32 次总尝试；
  消除不可观察的中间容器，逃逸、身份观察、EH/暂停仍保对象。实测消除 64 B/轮。
- IntervalNarrow：闭 i64 区间、合流凸包、写入 kill、有限扩张到 Top；
  完整收敛后至多 32 点，自动拆箱只替换已证明安全的原动态加法。
- 叶特化：不可变私有原函数锚点与递归深度检查保正确性，
  实参已有 exact-I64 证明才成为实验候选，身份/溢出失败仍调用原函数。
- 迭代融合、LICM、容器特化完成实际 IR 研究，但未实施、不报收益；
  研究文件与 probe 源码/IR 均归档，不能用“研究完成”替代生产功能。

## 性能口径

专项同时保默认层次化与禁 tier，交错进程、所有原始样本、分配和实际 JIT 代码，
不利对照完整保留。区间未知溢出对照时间不利且原因尚未唯一确定，
虽禁 tier caller/callee 实际汇编逐字相同，也不称 GC/布局风险已经被证明不存在。

完整现有基准实际为 26 个，历史 M2.12 的 22 个与后加 Phase 3 不能混为同一分母。
进程墙钟与 `main_ms` 分开；后者仍包含该进程用户代码 JIT，runner 的跨进程
warmup 不是充分同进程稳态。四核心另测实际编译函数的预热 kernel，输入重建
置于计时外，并明确 Mandelbrot kernel 不含原字符串/输出成本。
当前 Release Rust CLI 与保存的 e1c Debug Rust CLI 产出都使用同一 Release runtime；
编译耗时可分别记录，但不能据不同 Rust profile 比较编译器提速。
整 26 项逐 benchmark 轮转比较已完成 432 个进程，全部输出与固定基线一致。
排除 hello、只取默认 variant 的 25 项进程 main 几何比为默认层次化 +2.8%、
禁 tier -5.3%；其中默认 closures +64.6%、dict_ops +24.6% 等不利值原样保留。
这不是整个项目默认净提速证据，也不是四核心充分预热 kernel 的结果。
四核心预热 kernel 的 80 个独立进程已全部语义通过；默认层次化 fib / Mandelbrot /
矩阵乘法 / N-Body 耗时分别变化 -1.2% / +5.0% / +1.5% / +0.1%，禁 tier 则为
-9.2% / -3.4% / -10.5% / +4.5%。矩阵约 144.67 MB、N-Body 679,309,624 B 的
每 kernel 分配并未消除；这两项当前 kernel 仍慢于相同口径 CPython，不隐去。
资源 JitInfo 是全进程指标；样本间 JSON 可能引发后台 tier，不能称默认进程已完全
停止编译。已计划 16 个实际 JIT 进程全部通过并归档；禁 tier 四核心两方 Diffable 全文相同，
默认矩阵/N-Body相同，fib版本数及Mandelbrot末层代码有差异。
不再为追求有利数字重复统计或新增实验。
不将专项倍数外推成项目性能或 80% 项目兼容率。

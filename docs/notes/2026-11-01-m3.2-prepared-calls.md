# M3.2：暂停调用目标提前绑定

参数里的yield把调用拆成两段。Python要求先固定函数/方法，再求参数；旧DynCallMethod把属性查找
推到所有参数求完之后，会观察到暂停期间替换的新方法，还会延迟property和缺属性错误。
新HIR PreparedCall标记此类无星号调用，MIR先固定目标到临时局部，再降级参数，见ADR-0020。

普通对象立即GetAttr；内建方法通过PrepareMethod保存receiver/name/类型静态入口，恢复不再查属性。
不可调用属性直到参数全部求完才报TypeError；缺属性则在第一次参数yield之前报AttributeError。
普通无暂停调用的PIC和分配路径不变，暂停路径显式承担绑定对象与保存局部的成本。

审阅发现旧内建便利分派有clear/upper等忽略额外参数、dict.get缺参越界的风险。prepared入口先
校验支持的min/max，再执行副作用；测试锁定clear/pop失败不改变容器，所有绑定名过量参数均拒绝。
这不冒称已同时修复普通无暂停路径的历史arity缺口，后续应统一其签名验证。

直接dataclass构造实测仍依赖原专用字段ABI，不能改成普通PyClass调用，故目前报E0305；其余
内建多参/关键字构造ABI未完备者在HIR报E0100。单位置构造、print/abs和普通函数/类/方法均有
正向暂停差分；星号实参展开时机仍待独立竖切，不静默越过边界。

pending先跑CPython再差分转正，覆盖方法/函数替换、property一次求值、缺属性早错、noncallable
晚错、receiver身份、关键字、多个暂停参数、lambda默认值、普通类构造、sort关键字及错误副作用。
`make runtime` / `make check` 全绿：67条编译e2e、18条跳过、81条CPython基线/框架、124条C#单测，
Rust lint/单元/快照通过。项目兼容率继续按固定集实测，而非用本语法通过率计数。

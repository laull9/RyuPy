# M1.0 曳光弹：从 Python 源码到 .NET CIL 的全链路闭环

- 日期：2026-10-31
- 关联里程碑 / ADR：M1.0

## 做了什么

打通了 RyuPy 第一颗「曳光弹」（Tracer Bullet）的最窄端到端闭环，成功将 `print(1 + 2)` 编译并在 .NET 运行时上正确打印出 `3`：

1. **HIR Lowering (`ryupy-hir`)**：
   - 遍历 Ruff AST 顶层语句，将表达式语句收拢进隐式入口函数 `main`；
   - 仅降级整数字面量、加法操作符 `+`、内建函数 `print`，其他语法统一报错 `E0100` 并产出 `ExprKind::Missing` 容错节点。
2. **Type Check (`ryupy-ty`)**：
   - 旁表记录表达式类型：整数字面量推导为 `Ty::Int`，加法要求双侧均为 `Ty::Int` 并产出 `Ty::Int`；
   - `print(...)` 检查参数类型并在旁表中标记返回类型为 `Ty::None`。
3. **MIR Build & Validate (`ryupy-mir`)**：
   - 将嵌套表达式展开为临时局部变量与平铺的三地址指令：`_0 = Add(1, 2)`；
   - 语义改写：将 `print` 展开为运行时调用序列 `WriteI64(_0)` 与 `WriteNewline()`；
   - 实现合法性验证（无 `Unreachable` 终结符残留、变量与基本块 ID 边界检查）。
4. **CIL Codegen (`ryupy-codegen-cil`)**：
   - 使用 `dotnetdll` 组装程序集，引用 `System.Runtime` 与 `RyuPy.Runtime`；
   - 将 MIR 基本块指令序列栈化（`ldc.i8`、`add.ovf`、`stloc`、`ldloc`、`call`、`ret`）；
   - 输出符合 ilasm 风格的 dump 文本。
5. **端到端测试与快照**：
   - 移除 `tests/e2e/phase1/m1_0_print_int.py` 的 `pending` 标记，差分测试通过；
   - 增加 HIR、MIR、CIL 三份 insta 快照测试。

## 踩到的坑

### 1. .NET PE 架构不兼容异常（ARM64 macOS）

- **现象**：生成的 `.dll` 在运行 `dotnet target/ryupy/...` 时报错：
  `Unhandled exception. System.IO.FileLoadException: Could not load file or assembly ... The assembly architecture is not compatible with the current process architecture.`
- **原因**：`dotnetdll` 的 `WriteOptions { is_32_bit: false, .. }` 默认输出 `IMAGE_FILE_MACHINE_AMD64` (x64) 架构标识。而在 Apple Silicon (ARM64) macOS 下，系统上的 `dotnet` 是本地 ARM64 进程，加载标明为 AMD64 专用的 PE 镜像时会拒绝执行。
- **解决**：根据 ECMA-335 (Partition II, §25.2.2)，纯托管的 AnyCPU 程序集在 PE 头中必须设置 `Machine = 0x014c` (`IMAGE_FILE_MACHINE_I386`) 并配合 CLR 头的 `COMIMAGE_FLAGS_ILONLY`，告诉运行时本镜像仅包含纯中间语言指令，由 JIT 负责编译为宿主机器码（无论是 x64 还是 ARM64）。在 `dotnetdll` 中设置 `WriteOptions { is_32_bit: true, is_executable: false }` 即可正确生成跨平台的 AnyCPU DLL。

### 2. `dotnetdll` 宏中 `#var` 与 `@var` 的语义差异

- **现象**：连续为多个方法引用替换同一个类类型变量时报 `use of moved value`。
- **原因**：在 `dotnetdll` 的宏（如 `method_ref!`）中，`#var` 表示移交所有权（move），而 `@var` 表示克隆（clone）。
- **解决**：对复用的类型引用变量使用 `@builtins_type`。

### 3. `Resolution` 的生存期参数

- **现象**：`Resolution<'a>` 编译报错指出返回了局部变量的借用。
- **原因**：若向 `Module::new` 传入 `&str`，其生命周期会绑定到局部字符串引用。
- **解决**：直接传入 owned `String`，利用 `Into<Cow<'static, str>>` 构造 `Resolution<'static>`，摆脱生命周期限制。

## 学到的概念

- **曳光弹原则**：先横跨各层打通最窄闭环，暴露系统边界问题（如运行时加载、PE 头部格式、ABI 约定），避免在前端过早过度设计。
- **平铺与栈化**：
  - HIR（树状嵌套）→ MIR（三地址语句序列，显式局部变量槽）→ CIL（逆波兰求值栈操作）；
  - `dest = a + b` 转化为 `ld a; ld b; add.ovf; stloc dest`。
- **ECMA-335 AnyCPU 布局**：了解了 CLI 规范中通过 PE/COFF 头与 CLR 头部标志位协商架构兼容性的机制。

# M3.2：send 与表达式 yield

yield 表达式在 HIR 中保留，MIR Suspend 带可选接收局部。帧新增槽 1 保存本次输入，恢复块
先取值再清槽；原局部从槽 2 起保存。复合表达式早先求出的操作数、容器元素和默认值同样随
局部 spill，不依赖 CLR 计算栈跨暂停。语句 yield 忽略输入但清除额外引用，见 ADR-0019。

运行时独立跟踪 started，首次非 None send 报错但保留未启动状态；next 与 send(None) 等价，
关闭后发送任意值耗尽，重入先报错。返回值一次性消费与错误关闭沿用上一切。

lambda 的 yield body 独立标记生成器；嵌套 def / lambda 默认值仍在外层恢复中执行。
推导式内部 yield 统一报 E0100（包括 dict key），但最左 iterable 属于外层，允许在该位置
暂停并接收之后传入的可迭代对象。模块默认值 / 类体不允许 yield，不能漏进后端变内部错误。

pending 先跑 CPython，再差分转正：普通接收、复合运算、容器临时量保存、循环、lambda、
默认值暂停、生成器表达式忽略send、最左iterable暂停、短路分支、参数错误与新建/耗尽规则。
运行时专测补重入优先、PEP479、返回值和帧输入布局。throw/close、yield from及跨暂停清理仍待做。

完整 `make runtime` / `make check` 通过：66 条编译 e2e、18 条跳过、80 条 CPython 基线 / 框架，
119 条 C# 单测及 Rust lint / 单元 / 快照。全局部spill代价仍在，不宣称性能收益。

当前还对调用实参内 yield、字典字面量内 yield、属性 / 下标增量赋值跨暂停报 E0100：
方法绑定、星号实参展开、哈希插入与目标保存的时序须在后续独立竖切完成，不能静默延后。
可以先把 yield 的接收值赋给局部，再进行这些操作；不把该限制冒称完整表达式兼容。

固定项目集重跑仍为 0/20 原生通过。审阅把调用参数暂停的提前绑定 / 展开问题明确纳入后续
求值准备竖切，而不是在首切用错误次序继续执行；TODO逐项保留这些已知待补边界。

tuple / set 的星号展开含 yield 同样明确拒绝：现有展开临时列表尚需保留最终类型与集合哈希时序；普通列表星号展开不受此项限制。

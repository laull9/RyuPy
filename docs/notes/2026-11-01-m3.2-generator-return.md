# M3.2：生成器返回值与一次性完成消费

MIR 不再丢弃普通生成器完成边的返回操作数。PC -1 标记完成，恢复委托的返回值携带终值；
运行时通过本次调用的 out 参数传递，而不是在生成器对象里缓存。for/list 的 MoveNext 直接
丢弃终值，next(default) 返回默认值，只有无 default 的首次完成 next 抛带 value 的 StopIteration。

完成信号在恢复核心的 PEP 479 捕获区外抛出，不能误认为用户抛出的 StopIteration。
终值为 None 时 value 为 None、args 为空；其它对象作为单个原参数，tuple 不展开、列表身份保留。
普通生成器异常仍关闭并释放帧，不出现旧终值可领取状态。生命周期取舍见 ADR-0018。

新增 pending 后先验证 CPython，再差分转正，覆盖首次 / 再次耗尽、__next__、list / for / default
消费、break 尚未耗尽、返回值副作用、对象身份与三种 None 结束路径；运行时专测补充帧释放、
默认值不吞 PEP 479 错误。通用显式 StopIteration 构造的参数数组 ABI 缺口没有在本切冒称修复。

`make runtime` / `make check` 全绿：65 条编译 e2e、18 条跳过、79 条 CPython 基线 / 框架用例、
114 条 C# 单测，Rust lint / 单元 / 快照通过。固定项目重跑仍 0/20 原生通过，阻塞未改变。

审阅发现完成异常构造过早格式化终值会触发用户 __str__，甚至把正常结束变成 ValueError。
现将消息属性改为惰性读取，Render单次缓存局部而非永久缓存；差分和专测覆盖构造无副作用、
多次格式化读取可变对象新内容、__str__抛错只在格式化发生。

未捕获错误另加退出码1的fixture：报告格式化遇用户__str__抛错时输出
`StopIteration: <exception str() failed>`，不从入口异常处理器泄漏CLR未处理异常；
用户显式str(error)仍正常传播格式化异常。

# M3.1：生成器表达式接入普通状态机

最左 iterable 在外层立即求值并取得迭代器；隐式 `<genexpr>` 只接收该迭代器，不复制或
重新调用用户 `__iter__`。元素、过滤器、内层 iterable 在恢复时依次求值，异常后永久耗尽。

复用 ADR-0016 的独立作用域与共享 cell，同时复用 ADR-0017 的堆帧状态机。急切推导式继续
创建结果容器并插入；生成器表达式只发 Yield，没有隐藏结果槽或容器分配。两者共享循环和
过滤器构造，MIR / CIL / 运行时无需新增生成器表达式专用 ABI。全局部 spill 成本仍存在，
此处只避免错误的急切物化，不宣称整体快于 CPython。

pending 差分先跑 CPython，再验证最左求值 / 取迭代器日志、非迭代对象立即报错、逐元素惰性、
内层 iterable 延后、外层同名绑定、捕获 cell 后续修改、lambda 晚绑定与默认捕获、嵌套推导式、
星号解包、空迭代与异常终止。async、海象、类体、生成器表达式内零参 super 仍明确拒绝。

普通 yield 首切的 send/throw/close、return value 与跨暂停清理限制不因接入生成器表达式而解除；
M3.2 完整协议仍待后续竖切。项目兼容率继续由固定入口实测，不用表达式语法通过率代替。

完整 `make runtime` / `make check` 通过：63 条编译 e2e、18 条 pending 跳过、77 条 CPython
基线 / 框架用例、108 条 C# 单测及 Rust lint / 单元 / 快照。固定项目集再跑仍 0/20 原生通过，
没有改变分母或引入桥接。工具链与普通 yield 首切一致。

审阅补充修正了生成器扫描边界：不能跳过嵌套 def / lambda 的默认参数表达式，因为它们仍在
当前恢复作用域执行。扫描只跳过内层函数体，保留默认值的零参 super 诊断；三条负例快照锁定
普通生成器的 lambda / def 默认值与生成器表达式中的 lambda 默认值，避免漏掉上下文限制。

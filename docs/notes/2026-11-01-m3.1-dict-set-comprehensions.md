# M3.1：字典与集合推导式

## 复用而非复制作用域实现

在 list 首个竖切之后，`comprehension_ast.rs` 为 list/dict/set 提供借用 AST 视图，保留结果种类、
生成器子句和 key/value；闭包发现、父作用域划分、局部预登记、最左 iterable 的外层求值规则
都走同一条路径。MIR、后端与运行时 ABI 不变。隐式函数的分配取舍仍见 ADR-0016，未做性能宣称。

集合结果初始化为空 set，每个通过条件的元素执行 add，重复元素也不能省掉表达式副作用。
字典最容易出错：普通 `mapping[key] = value` 的 Python 规则是先求 value 再求 key，但推导式
要求先 key 后 value。因此先把 key 求值保存到隐藏 `.key`，然后复用下标赋值；哈希和插入仍在
value 求值之后发生。非法键测试明确要求 value 的副作用保留，key 本身抛错时 value 不执行。

## 合法键哈希副作用

审阅要求补充自定义键的 `__hash__` 日志，发现已有 `PyDict.Set` 先查找再索引器插入，会对非首个
新键重复哈希。改用 .NET `CollectionsMarshal.GetValueRefOrAddDefault` 一次查找完成登记；
写好槽位下标后不再持有该 ref 跨索引变更。已有键仍覆盖原位置，不改变结构版本。
这既去掉重复查找，也保留 Python 一次插入一次哈希的可观察行为；没有未经测量的速度倍率承诺。

## 验收边界

分别新增 pending dict/set 用例，先在 CPython 验证，再转正；原混合推导式用例也转正。
差分覆盖重复键保序、同名外层绑定、多层 for/if、元组目标、逃逸闭包、混合嵌套、集合去重、
不可哈希元素及 key/value 异常顺序。三类共同的海象/异步/类体拒绝仍明确报诊断。

生成器表达式仍未实现：它需要最左 iterable 立即取迭代器、后续惰性执行，不能复用急切容器
假装完成。M3.1 的相关条目保持待做，随 M3.2 状态机接续。项目通过率仍独立由固定入口实测。

`make runtime` / `make check` 全绿：61 条编译 e2e 通过、18 条 pending 跳过，75 条 CPython
基线与框架自检、100 条 C# 单测、Rust lint/单测/快照通过。平台为 Linux x86_64，工具链同 list 竖切。

# M3.2：星号容器的类型与插入顺序

旧通用star展开把tuple/set都当临时list返回。本切在独立container_literals构建中修正：tuple在
全部展开完成后冻结；set先求首star前的全部元素再MakeSet，后续逐元素SetAdd或流式SetExtend。
不会等后续yield结束才hash前面的元素，也不会把整个迭代器先物化后才发现首元素不可哈希。

新增pending差分先跑CPython再转正，覆盖普通和暂停路径最终类型、去重、修改源不回溯前缀、
set前缀求值/哈希顺序、next与hash交错、非法源/元素在下次暂停前报错及错误后耗尽。
运行时专测覆盖失败保留已插入前缀、目标类型诊断与set/frozen内建键来源。

缓存hash的源集合复制不能用一般流式重hash冒充。实测.NET10 UnionWith空/非空目标均重hash，
copy构造虽可复用却不足以完成通用合并；因此对源集合含用户对象明确NotImplementedError，扫描
不执行用户hash/eq。`m3_2_set_cached_hash.py`保留pending，C#测试锁定构造源后改hash抛错也不会
重新调用。ADR-0021记录为未支持而非可接受性能偏差，后续需独立缓存hash存储设计。

验证：`make runtime`、`make check` 全绿：C# 131 项，编译差分 68 通过/19 忽略，
CPython 基线与框架 83 项。`make projects` 固定项目仍 native 0/20，不据语法用例外推兼容率。

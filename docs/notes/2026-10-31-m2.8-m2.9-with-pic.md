# M2.8 / M2.9 上下文管理、项目切片与有界 PIC

- 日期：2026-10-31
- 关联里程碑：M2.8、M2.9
- 关联 ADR：[ADR-0012](../adr/0012-bounded-dynamic-pic.md)
- 目标用例：`m2_8_with`、`m2_9_matrix_nbody`、`m2_9_pic`、`m2_9_long_run`、
  `cases/harness/pipeline`

## 做了什么

### M2.8：`with`

`with` 没有在 MIR / codegen 里新增节点，而是在 HIR 去糖成已有的 `try` / `except` / `finally`：

```text
mgr = ctx
exit = mgr.__exit__          # 与 CPython 一样，在 __enter__ 之前取出
value = mgr.__enter__()
x = value
handled = False
try:
    body
except BaseException as exc:
    handled = True
    if not exit(type(exc), exc, None):
        raise
finally:
    if not handled:
        exit(None, None, None)
```

这样做的好处是异常区域、`return` / `break` / `continue` 的清理边、`finally` 状态机全部复用
M2.2 的实现。多上下文按源码顺序嵌套，外层 `try` 包住内层的 `__enter__`，所以内层进入失败时
外层仍会收到异常并清理。`handled` 标记保证每次进入只调用一次 `__exit__`；被抑制的异常不再
进入 finally 的正常退出分支，重新抛出的异常由外层 finally 通道接管。

`with` 展开会生成多条语句，但 `lower_stmt` 的约定是返回一条，因此外面包一层恒真的
`if True:`。条件恒真，MIR 会直接走 then 分支，不影响作用域与跳转语义。

### M2.9：项目切片、长跑与 PIC

1. **多文件数据处理样例**（`cases/harness/pipeline`）：包内模块共享列表状态、单继承与
   `super()`、动态函数调用、异常恢复、`with` 清理与 `global` 重绑定都在一个入口里跑通。
2. **矩阵乘法 / N-Body**：`m2_9_matrix_nbody` 转正，覆盖嵌套容器、`for` 循环、普通对象
   列表与浮点更新。
3. **PIC**：codegen 给每个动态二元运算 / `CallValue` / `CallMethod` 分配程序内唯一的调用点
   编号，运行时 `PyPic` 做有界缓存。详见 ADR-0012。
4. **长期运行**：`m2_9_long_run` 跑 2 万项列表、5000 键字典（删除一半）、5000 次集合插入，
   以及 1000 次重复导入并修改模块状态，验证容器扩容、模块缓存与重复导入。
5. **模块搜索根**：`BuildOptions.search_paths` + CLI `-I/--search-path`；项目 runner 自动把
   项目源码与依赖的 `third_party/` 目录加入搜索路径。
6. **基准**：新增 `tests/benchmarks/*.py` 与 `tests/run_benchmarks.py`，`make bench` 对比
   CPython 与 Release 产物。

## 踩到的坑

- **父包没有自动初始化**：`import a.b.c` 时只登记了 `a` 与 `a.b.c`，漏掉 `a.b`。原因是
  `package_prefixes` 返回的是「除自身以外的所有前缀」，父包计算又传了 `parent`，少了一层。
  修复为对完整模块名取前缀；运行时 `PyModules.Import` 也补上「先导入父包、返回后重新查缓存」，
  并把子模块挂到父包属性上。`m2_9_long_run` 直接导入 `fixtures.module_case.state` 时暴露了它。
- **对模块调用方法**：`PyOps.CallMethod` 的属性协议分支漏了 `PyModule`，`pkg.func()` 会落到
  内建方法 switch，报 `'module' object has no attribute ...`。补上 `PyModule` 后与属性读取一致。
- **PIC 不能缓存模块属性**：模块 getter 已经是静态槽位读取，且模块可以在运行期重绑定；
  方法缓存只针对普通实例 / 类方法，模块每次重新取值。
- **方法缓存的失效键**：只比较类版本不够——实例属性可以遮蔽方法，也可以删除后恢复。因此条目
  同时保存类全局版本与实例属性修改版本；只持有类和函数，不持有实例，避免缓存把对象拖住。
- **PIC 的调用点编号放在 codegen**：MIR 不引入后端相关的 site 字段；codegen 按函数顺序递增
  分配即可保证程序内唯一。这样 MIR 快照不受影响，CIL 快照能看到编号。

## 基准

命令：`python3 tests/run_benchmarks.py`（会先构建 Release CLI）。环境：macOS arm64、
.NET 10.0.403、CPython 3.13.13、Release 配置；1 次预热 + 5 次中位数，不含构建与 JIT 时间。

| 基准 | 输入 | CPython (ms) | RyuPy (ms) | 相对 CPython |
| --- | --- | ---: | ---: | ---: |
| fib | `fib_rec(30)` + 20 万次 `fib_iter(90)` | 282.8 | 153.5 | 1.84x |
| mandelbrot | 内部区域 240×120、1000 次上限 | 1216.6 | 273.8 | 4.44x |
| dynamic | 300 万次动态加法 + 200 万次方法调用 | 162.2 | 791.6 | 0.20x |

动态基准在同一 DLL 上切 `RYUPY_PIC=0` 为 819.0 ms，PIC 约快 3.3%。收益不大但稳定，
未命中完整回退，因此默认开启；若后续运行时变化导致收益消失，改 `PyPic.Enabled` 默认值即可。

> 早期笔记里的 6.2x / 6.1x 是更小的输入与不同的 CPython 版本；本表以当前固定输入为准。

## 项目矩阵

`make projects` 现在会带上 `third_party/` 搜索根，20 个项目都能解析到源码，状态全部是
`unsupported`，但阻塞从「找不到第三方包」推进到真正的语言 / 标准库缺口：内建容器与字符串继承、
属性表达式基类、`NamedTuple` / 动态基类、类装饰器、函数内 `import`、`map` / `ord` / `dir` /
`open` 等内建。逐项目的最短阻塞写在 `docs/compatibility.md` 的矩阵里。

## 还没想明白的

- 内建容器继承（`class X(list)` / `dict` / `str`）需要决定表示方式：运行时包装还是 CLR 子类。
  它同时影响 `isinstance`、`len`、迭代与 `__getitem__` 的优先级，适合单独一个竖切。
- 函数体内 `import` 需要决定编译期模块图是否包含「运行时才可达」的模块；当前只支持顶层导入。
- 方法缓存现在只缓存 `PyBoundMethod` + `PyFunction`。`property`、`classmethod` 与魔术方法槽
  仍有优化空间，但需要先确认失效键覆盖描述符。

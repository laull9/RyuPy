# M3.2：普通 yield 状态机首切

## 状态留在堆上，语义留在 MIR

HIR 当前函数扫描不进入嵌套函数 / 类 / lambda，不可达 yield 仍使函数成为生成器。
类型层把生成器固定为 Dynamic，返回标注不能让调用工厂变成普通函数执行。
MIR 先用 Suspend 显式表达暂停边，再统一降成工厂与恢复 CFG；codegen 只构造运行时委托。

帧保存局部、临时量、循环迭代器与共享 cell 引用；只有首次入口执行序言及 CellNew。
恢复入口是 arena 后追加的块，因此 CIL 必须尊重 Body.entry，不能隐含认为编号 0 总是入口。
每次恢复由运行时登记 traceback 并在返回 / 异常时清理，避免暂停后污染调用者线程状态。

当前保存所有局部，暂停 / 恢复开销均随局部槽位数增长；不宣称速度收益。后续可做存活性
裁剪和专用字段优化，先保语义，取舍见 ADR-0017。

## 已验证的行为与边界

pending 用例先在 CPython 验证，随后差分转正：惰性执行、yield None、不可达 yield、两个实例
交错、for/while 与 break/continue、外部 nonlocal 写入、自有 cell 及逃逸函数身份、未绑定局部、
完整函数标注、关键字 / 默认参数与调用时参数错误、异常后耗尽、重入、意外 StopIteration。
运行时专测覆盖释放帧引用、traceback 清理和原因链；MIR 专测拒绝未降级暂停与非法恢复 ABI。

只接受语句 yield、普通控制流、裸 return。生成器内 try/with、零参 super、return value、
表达式型 yield、yield from 明确 E0100；send/throw/close 显式 NotImplementedError。
零参 super 的方法上下文目前只包住工厂调用，不能静默让 next 在错误的上下文中恢复。
完整生成器与清理用例仍 pending，生成器表达式将另做独立竖切，固定项目分子不会因语法通过增加。

完整 `make runtime` / `make check` 通过：62 条编译 e2e、18 条 pending 跳过、76 条 CPython
基线 / 框架用例、108 条 C# 单测及 Rust lint / 单元 / 快照；项目集重跑仍 0/20 原生通过，
progress 当前首阻塞明确为生成器 with 的跨暂停清理。工具链与 M3.1 相同。

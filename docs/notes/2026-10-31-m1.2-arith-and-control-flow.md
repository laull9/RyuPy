# M1.2 运算与控制流：Python 语义算术、短路求值与基本块控制流图

- 日期：2026-10-31
- 关联里程碑：M1.2
- 目标用例：`tests/e2e/phase1/m1_2_arith.py`、`tests/e2e/phase1/m1_2_control_flow.py`

## 做了什么

打通了 Python 完整的算术、位运算、比较、一元与短路逻辑运算，以及基于基本块（BasicBlock）的控制流图（CFG）构建、条件分支、循环与 CIL 目标回填：

1. **HIR 降级与表达式去糖 (`ryupy-hir`)**：
   - **算子与类型映射**：新增 `operator.rs`，全面映射 `BinOp`（算术、整除、真除、位运算）、`UnaryOp`（正负、取反、按位非）、`CmpOp`（6 种比较）与 `BoolOp`（and/or）；
   - **链式比较展开**：在 `expr.rs` 中将 `a < b < c` 自动去糖展开为二元短路树 `(a < b) and (b < c)`；
   - **多元短路转二元**：将 Ruff AST 中的多操作数 `and` / `or`（如 `a and b and c`）递归折叠为左结合的二元短路树；
   - **控制流降级**：在 `lower.rs` 中支持 `if` / `elif` / `else`（递归展开为嵌套 if）、`while` 循环；
   - **循环外跳转静态拦截**：维护 `loop_depth` 深度计数，循环外的 `break` 或 `continue` 静态报出 `E0107` 编译错误。
2. **表驱动单态类型推导 (`ryupy-ty`)**：
   - **表驱动规则表**：新增 `ops.rs`，依据 `semantics.md` §3 实现二元、一元和比较运算规则表。例如：
     - 真除法 `/` 总是产生 `float`；
     - 整除 `//` 在整数间产生 `int`，浮点间产生 `float`；
     - 整数与浮点混合运算自动提升为 `float`；
     - 位运算严格限制为 `int`，对 `float` 报出 `E0203`；
   - **表达式类型检查接入**：在 `check.rs` 中接入 `ops.rs` 规则，对比较运算返回 `Ty::Bool`，并要求短路逻辑两端类型与条件表达式两分支类型保持一致。
3. **MIR 控制流图构建与优化 (`ryupy-mir`)**：
   - **表达式构建与语义改写**：新增 `expr_builder.rs`，将 `//`、`%`、`**` 改写为运行时辅助函数调用（`RuntimeFn::FloorDivI64` / `ModI64` / `PowI64` 等）；将 `/` 自动插入类型提升（`CastKind::I64ToF64`）；
   - **短路逻辑的基本块降级**：为 `and` / `or` 自动构建分支基本块，左侧求值决定是否短路，右侧仅在需要时求值；
   - **循环目标栈**：在 `build.rs` 中维护 `loop_stack: Vec<(continue_bb, break_bb)>`，正确引导 `break` 跳到循环退出块、`continue` 跳到条件求值块；
   - **按需分配死代码块**：避免函数在 return 之后盲目生成不可达的空基本块；
   - **控制流简化 Pass (`simplify_cfg.rs`)**：实现常量分支折叠（`Branch { cond: const true } → Goto`）、直接跳转链合并（`Goto A → Goto B → B`）与不可达块清理；
   - **验证器升级**：`validate.rs` 引入可达性分析，仅对可达基本块验证类型与终结符合法性。
4. **CIL 代码生成与分支目标回填 (`ryupy-codegen-cil`)**：
   - **两遍发射与分支回填（Backpatching）**：在第一遍发射各基本块指令时记录每个 `BlockId` 的起始指令下标，并记录所有跳转指令在 `instructions` 数组中的槽位；第二遍直接回填目标下标；
   - **比较指令序列生成**：针对 CIL 缺少 `cle` / `cge` 指令的特性，利用 `cgt` + `ldc.i4.0` + `ceq` 生成 `<=`，利用 `clt` + `ldc.i4.0` + `ceq` 生成 `>=`，利用 `ceq` + `ldc.i4.0` + `ceq` 生成 `!=`；
   - **位运算与一元指令**：支持 `and`、`or`、`xor`、`shl`、`shr`、`neg`、`not` 指令；
   - **托管运行时引用**：在 `assembly.rs` 中接入 `RyuPy.Runtime.PyMath` 外部静态方法。
5. **C# Runtime 算术支持 (`RyuPy.Runtime`)**：
   - 补全 `PyMath.FloorDivI64` 与 `ModI64`，并在除数为 0 时显式抛出 `DivideByZeroException`。
6. **全套门禁与测试通过**：
   - 去掉 `m1_2_arith.py` 和 `m1_2_control_flow.py` 的 pending 标记，e2e 测试与 CPython 输出 100% 一致；
   - 在 `snapshots.rs` 中补充了 M1.2 运算与控制流的 HIR、Types、MIR、CIL 全部 8 个阶段快照；
   - `make check`（代码格式、clippy `-D warnings`、全 crate 单元测试、dotnet 编译、e2e 测试）全绿。

## 踩到的坑

### 1. Python 负数整除与取模（Floor Division）的语义差异

- **现象**：在 C# / CIL 中，整数除法 `/` 与取模 `%` 是截断除法（向 0 取整，Truncated Division）。例如 `-7 / 2 = -3`，`-7 % 2 = -1`。但在 Python 中，整除 `//` 与取模 `%` 是向下取整除法（Floor Division，向负无穷取整），规范规定 `-7 // 2 = -4`，`-7 % 2 = 1`，且满足 `a == (a // b) * b + (a % b)`。
- **解决**：在 MIR 构建期不直接发射 CIL 原生的 `div` 指令，而是将 `//` 和 `%` 改写为对运行时辅助库 `PyMath.FloorDivI64` / `PyMath.ModI64` 的调用。在 C# 端按数学公式实现：
  ```csharp
  long q = a / b;
  long r = a % b;
  if ((r > 0 && b < 0) || (r < 0 && b > 0)) { q--; r += b; }
  ```
  严格保证行为与 CPython 逐位一致。

### 2. CIL 缺少 `cle` 与 `cge` 指令

- **现象**：CIL 指令集中只有等于 `ceq`、小于 `clt` 和大于 `cgt`，根本没有 `<=`（`cle`）和 `>=`（`cge`）。
- **原因**：CLR 设计者为了保持指令集精简，要求编译器通过组合或取反来表达小于等于和大于等于。
- **解决**：
  - `a <= b` 等价于 `!(a > b)`：先发射 `cgt`，然后将结果与 0 做等于比较（`ldc.i4.0; ceq`）；
  - `a >= b` 等价于 `!(a < b)`：先发射 `clt`，然后 `ldc.i4.0; ceq`；
  - `a != b` 等价于 `!(a == b)`：先发射 `ceq`，然后 `ldc.i4.0; ceq`。

### 3. dotnetdll 分支跳转模型与回填（Backpatching）

- **现象**：CIL 字节码中的分支指令在二进制层面是基于相对字节偏移（Byte Offset）跳转的，但我们使用的是 Rust 的 `dotnetdll` 库。
- **机制发现**：`dotnetdll` 的 `Instruction::Branch(usize)` 与 `Instruction::BranchTruthy(usize)` 接受的数值不是字节偏移，而是**目标指令在 `instructions: Vec<Instruction>` 中的数组索引**！在写入 PE 文件时，`dotnetdll` 内部会根据指令长度自动计算真实的字节偏移。
- **解决**：我们在 `stackify.rs` 中采用两遍发射：
  1. 第一遍按基本块顺序线性发射指令，记录每个基本块第一条指令在数组中的下标 `block_start_indices: HashMap<BlockId, usize>`；
  2. 遇到 `Goto(target)` 或 `Branch { then_, else_ }` 时，先发射一个占位索引（如 0），并记录待回填的指令数组索引与目标 `BlockId`；
  3. 全部基本块发射完成后，遍历待回填列表，将占位符直接替换为真实的目标指令索引。

### 4. 函数末尾 Return 导致的不可达死块与 MIR 验证

- **现象**：最初在处理 `StmtKind::Return` 时，每次发射完 Return 就立即 `current_bb = self.new_block()`。对于以 `return` 正常结束的函数，其末尾无条件产生了一个空的不可达基本块 `bb1: { return; }`。对于有返回值的函数，空块中的 `Return(None)` 导致验证器报错。
- **解决**：
  1. 改用**按需分配（Lazy Dead Block Allocation）**：处理 `Return`、`Break`、`Continue` 时仅标记当前块终结，不预先分配新块；只有当后续确实存在不可达语句时，才开辟死代码块承载它们；
  2. 在 `validate.rs` 中增加从 `entry` 出发的 BFS 可达性遍历，只对可达基本块验证终结符完整性与返回值类型。

## 学到的概念

- **控制流图（Control Flow Graph, CFG）**：将线性代码根据控制流分界（分支、跳转、返回）划分为基本块，每个基本块内部只有单入口和单出口，块末尾以终结符（Terminator）连接其他基本块。
- **短路求值（Short-circuit Evaluation）与分支映射**：`a and b` 和 `a or b` 在语言层面是表达式，但在中端 MIR 层面本质上是控制流分支：`a and b` 相当于「如果 a 为假则短路为 a，否则求值 b」。
- **循环目标栈（Loop Stack）**：通过在构建器中维护循环上下文栈 `(continue_target, break_target)`，可以优雅地支持任意深度的循环嵌套，并在遇到 `break` / `continue` 时瞬间查找到正确的跳转目标。
- **两遍发射回填（Backpatching）**：在未知跳转目标指令位置时，先发射占位符并在符号表确立后回写修正，是编译器后端生成分支代码的标准范式。

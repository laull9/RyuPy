# M2.7 模块系统：模块图、静态槽位与运行时导入

- 日期：2026-10-31
- 关联里程碑：M2.7
- 目标用例：`tests/e2e/phase2/m2_7_modules.py`、`m2_7_cycles.py`、`m2_7_import_retry.py`、
  `tests/cases/harness/multifile`、`tests/cases/errors/missing_module`

## 做了什么

把「一个 `.py` 一个程序」扩展成「一个入口 + 一棵可达模块图」，并让模块变量真正成为
跨函数、跨模块共享的存储。

1. **driver（`modules.rs`）**：从入口文件出发，解析 AST 收集 `import` 请求，按模块名在
   入口目录（等价 `sys.path[0]`）解析 `<a>/<b>.py` 或 `<a>/<b>/__init__.py`，同时补上父包。
   找不到的模块不报编译错误，留给运行时抛 `ModuleNotFoundError`。
2. **HIR**：新增 `ModuleVar` 与 `ExprKind::ModuleVar` / `AssignTarget::ModuleVar`；顶层赋值、
   `global` 声明、导入绑定以及 `__name__` / `__package__` / `__file__` 都登记为模块变量。
   `import` 保留成 `StmtKind::Import` / `ImportFrom`，相对导入在这里换算成绝对模块名。
3. **ty**：给模块变量推断「保守的槽位类型」：字面量、同类运算、dataclass 构造与引用已知
   变量可得到静态类型；`global` 声明过或无法推断则为 `Dynamic`。若模块入口最终降级为动态
   执行，所有槽位也统一装箱——动态执行可能出现 BigInteger 等静态槽位放不下的值。
4. **MIR**：模块变量是静态槽位；读写在静态路径上保持类型，在动态函数里自动装箱/拆箱。
   新增 `ImportModule` / `ImportAttr` 两个运行时调用。
5. **多模块合并（`link.rs`）**：每个模块单独构建 MIR，再按模块顺序重新分配 ID、加前缀
   合并成一个程序集；函数方法名、CLR 类名、静态字段名都在这里去重。
6. **codegen / runtime**：每个模块生成初始化入口与 `__mod_get_<i>` / `__mod_set_<i>`，
   由 `PyModules.Register` 登记。运行时 `PyModule` 持有名字、包名、文件、初始化委托与
   动态属性字典；`Import` 先登记「初始化中」再执行，失败移除缓存，循环导入因此能看到
   部分初始化对象。

## 踩到的坑

- **静态槽位 vs. 动态值**：模块变量原本只存在于 `main` 的局部变量里，改为静态槽位后，
  动态执行路径上的 BigInteger / 列表写回 `int64` 槽位会溢出或截断。解决办法是「入口动态
  则槽位也动态」，而不是在赋值处猜类型。
- **类型旁表在动态函数里不给表达式类型**：`NewObject` 的结果仍是静态 `Class` 操作数。
  装箱/拆箱必须以操作数为准，于是 `coerce` 增加了 `operand_type` 查询。
- **静态字段访问要求操作数是局部变量**：模块变量是 `Operand::Global`，访问 dataclass
  字段前先搬到临时局部。
- **委托签名**：`MethodSignature::new(instance: bool, ...)` 的第一个参数是「是否实例方法」，
  模块 getter / setter 必须传 `false`，否则 `ldftn` 指向实例方法，CLR 在创建委托时直接
  抛 `ArgumentException`。
- **逐帧文件名**：traceback 原来只有一个全局文件名字段；多模块后改为 `PushFrame(file, name)`
  按帧记录，否则导入模块里的异常会显示入口文件名。

## 已知边界

- 导入只支持编译时可达的模块；`from x import *` 与函数体内 `import` 明确报错。
- 命名空间包、自定义 import hook、动态模块名与热重载不在本阶段。
- 模块属性写入静态槽位时会按槽位类型转换（如把 `True` 写进 `int` 槽位得到 `1`）；
  常见用法下与 CPython 一致，跨类型重绑定属于后续动态槽位的工作。

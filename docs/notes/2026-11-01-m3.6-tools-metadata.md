## 本轮修复的实质问题

- chain 内层 iter 创建失败后不能继续取下一个 iterable；islice 不得多消费边界外元素。
- Counter 空映射更新直接复制，非空时采用新值加旧值；defaultdict 失败更新保留此前已写项。
- native dict 子类不能在复制、关键字展开和 JSON 中被当作普通键序列；可变包装不可 hash。
- contextmanager 装饰器执行 C# catch 时仍须进入 Python 异常上下文，finally 恢复调用者。
- from None 只抑制报告链而不抹除 context，显式 cause 不复制异常对象；报告链防身份环。
- 数据类生成 eq 是同类字段值比较，而非旧静态对象的身份比较；factory 缺省需与显式 None/MISSING 区分。
- post_init 是否调用在生成 init 时冻结，已存在的方法重绑定仍在构造时可见，之后新增不凭空生效。
- 动态 if 的确定赋值集合必须在分支克隆并在汇合取交集，否则缺失 UnboundLocalError 检查。
- pow 是可供 partial 使用的一等值；整模幂保负模/模逆规则，浮点错误不能直接透传 Math.Pow 的 inf/NaN。

## 性能不是文档上的延期

正确数据类表示初版确实比旧静态字段路径慢，不能只登记退化就结束。
已实施生成 init 身份/类版本守卫的槽位构造，随后在 MIR 去掉死 Use/Box；
实测分配量构造 120→72 B/对象，字段循环 47.96→24 B/轮，重复热测及原始结果见
[性能记录](2026-11-01-m3.6-dataclass-performance.md)。
已接入单次内部累加槽，把不可观察局部的数值结果延迟装箱；严格限定入口自然循环与使用关系，
保留 overflow/类型变化/自定义 inplace 协议回退。实际编译字段循环额外提升 1.48×/1.59×，
一百万轮分配 23,995,720→360 B，单函数仍约72 B；对应匹配路径默认启用。

# M3.1：列表推导式的第一个竖切

## 实现路径

先新增 pending 差分用例，覆盖外层同名变量、多层循环和过滤、空序列、解包、异常、闭包晚绑定、
默认值捕获、嵌套推导式与副作用顺序。闭包收集器将推导式拆为两种上下文：最左 iterable 留在
外层，其余部分建立新函数作用域。`closures_find` 按源码范围找回推导式，`lower_fn` 分配隐藏
参数与本地绑定，`comprehensions.rs` 生成结果列表、嵌套 ForEach / If、append 和 return。

MIR、代码生成和动态运行时复用既有路径，没有跨层读取 AST，没有新增 RuntimeFn。
性能取舍见 ADR-0016：隐式函数调用是首版代价，不在循环每步创建环境，不据此宣称速度提升。

## 测试暴露的旧问题

- Linux x86_64 上最小 print 用例虽然输出正确，却以 254/255 退出：入口使用 `Method::new`
  手工填局部变量，但未启用 initialize_locals。成功路径读取了未初始化的退出码。改用
  `Method::with_locals`，增加读取序列化 PE 方法头的单测与正常退出 e2e；转储也按真实 flag 输出。
- `PyIter.CreateFromObject` 递归调用返回对象的 `__iter__`，重复副作用且允许返回 list。
  改为验证返回值已是 IPyIterator 或带 `__next__` 的普通实例，不重新取得迭代器。
  新增 C# 单测及 CPython 差分，包含非法返回对象的立即 TypeError。

- 审阅补充星号解包用例后发现旧 MIR 将 tuple 切片直接写入 `*rest`，返回了 tuple。
  现在星号中间段经已有 list 内建转换，保证结果为新列表；不急切物化整个输入，不改普通分支。

## 验证边界

工具链为 Linux x86_64、Rust stable 1.99.1、.NET SDK 10.0.403、CPython 3.12.13。
`make runtime` / `make check` 全绿：58 条编译 e2e 通过、19 条 pending 跳过、73 条 CPython
基线/框架自检、99 条 C# 单测、Rust lint/单测/快照通过。逐层 HIR / Types / MIR / CIL 与
海象/异步/类体诊断已保存。固定项目集仍为 0/20；tomli、networkx、texttable 的首个阻塞已更新。
另外将三份旧诊断快照的宿主临时目录归一为文件名，保留源代码位置和完整错误。
list 的完成不代表 dict/set 或惰性生成器表达式可用，也不直接增加固定项目原生通过率。

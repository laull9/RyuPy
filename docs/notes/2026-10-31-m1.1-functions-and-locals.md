# M1.1 函数与局部变量：跨函数控制流、作用域分析与栈帧分配

- 日期：2026-10-31
- 关联里程碑：M1.1
- 目标用例：`tests/e2e/phase1/m1_1_functions.py`

## 做了什么

打通了用户自定义函数、参数传递、跨函数相互调用与前向引用、局部变量推导以及确定赋值分析的完整链路：

1. **HIR 作用域与两遍降级 (`ryupy-hir`)**：
   - **两遍扫描**：第一遍收集顶层所有 `def` 放入 `GlobalScope`，分配 `FuncId`，使得函数之间可以任意互相调用或前向引用（无需向前声明）；
   - **赋值即局部（Assign-implies-local）**：通过 `collect_assigned_names` 预扫描函数体内所有赋值目标（递归遍历控制流但不穿透内部嵌套 def），分配局部变量槽位；
   - **语义约束**：在函数体内若读取模块级变量，静态报出 `E0105` 错误；禁止 `global` / `nonlocal`（报 `E0103`）；
   - **格式化 dump**：重写 `pretty::dump`，输出接近 Python 源码缩进的直观 HIR 文本。
2. **并查集单态类型推导 (`ryupy-ty`)**：
   - 手写无外部依赖的并查集推导上下文 `InferCtx`（支持路径压缩与按秩合并），并支持 `Ty::Error` 毒化类型抑制级联报错；
   - 检查函数签名：顶层函数参数与返回值必须完整标注（缺标注报 `E0201`）；
   - 函数体内局部变量通过并查集推导单态具体类型，类型冲突报 `E0203`（并标注期望类型来源），函数调用匹配参数个数（`E0204`）与参数类型；
   - 实现 `ModuleTypes::dump`，格式化呈现每个函数的形参类型、返回类型与局部变量类型。
3. **MIR 流程与确定赋值分析 (`ryupy-mir`)**：
   - 预分配 `FnId`，将调用降级为 `Callee::Fn(fn_id)`，并将函数参数挂载为 `func.params: Vec<LocalId>`；
   - **确定赋值分析（语义陷阱 #10）**：在 MIR 构建期追踪局部变量初始化状态。形参在入口默认已赋值，普通局部变量在赋值前被读取时，报出 `E0301` 编译错误（避免 CIL 将其默认为 0 而与 Python 产生行为差异）；
   - **rustc 风格 pretty dump**：格式化输出带局部变量列表、基本块 `bb0: { ... }`、函数调用的 MIR 结构。
4. **CIL 代码生成与栈帧分配 (`ryupy-codegen-cil`)**：
   - **槽位分离**：彻底厘清 CIL 中形参（Arguments，对应 `ldarg` / `starg`）与局部变量（Locals，对应 `ldloc` / `stloc`）的区别，为非参数局部变量在 `.locals init` 中独立编号；
   - **动态方法签名构造**：通过 `dotnetdll` 的 `MethodSignature::new`、`ReturnType` 与 `Parameter` 动态构建托管静态方法；
   - **多方法与内部调用**：为模块中所有函数在 `RyuPy.Generated.Module` 中生成静态方法，通过 `Instruction::call(method_idx)` 实现高效率直接静态调用；
   - **溢出算术与返回值**：增加 `sub.ovf`（`BinOp::Sub`）、`mul.ovf`（`BinOp::Mul`）与 `Instruction::Return`。
5. **端到端验证与快照**：
   - 移除 `m1_1_functions.py` 的 pending 标记，端到端测试与 CPython 输出完全一致；
   - 更新并补充 M1.1 的 HIR、Types、MIR、CIL insta 快照与未赋值局部变量报错测试；
   - `make check`（代码格式、clippy `-D warnings`、全 crate 单元测试、dotnet 编译、e2e 测试）全绿。

## 踩到的坑

### 1. CIL 参数槽与局部变量槽的割裂

- **现象**：在最初构思时，MIR 将参数和局部变量都放在了 `func.body.locals` 中，如果直接按其局部变量下标生成 `ldloc`，在 CIL 中会导致未初始化局部变量或者索引越界。
- **原因**：CLR 的执行模型中，静态方法的入参通过 `ldarg.0`, `ldarg.1` 从参数列表读取，而局部变量槽通过 `.locals init (...)` 声明并用 `ldloc.0`, `ldloc.1` 读取，两者是两套完全独立的索引体系。
- **解决**：在 `lower_function` 中，先扫描 `func.params` 分配 `param_slots: LocalId → u16`，然后对剩余的局部变量在 `.locals init` 中分配 `local_slots: LocalId → u16`。读取或存储时根据所属集合分别发射 `LoadArgument` / `StoreArgument` 或 `LoadLocal` / `StoreLocal`。

### 2. `dotnetdll` 动态方法签名的组装

- **现象**：`dotnetdll` 提供了便捷的 `msig!` 宏（例如 `msig! { static void (string[]) }`），但在编译任意用户定义函数时，参数个数和类型是动态的，宏无法直接处理动态 Vec。
- **原因**：需要直接使用 `dotnetdll` 底层的结构体构建方法签名。
- **解决**：利用 `types.rs` 中的转换函数将 `MirType` 映射为 `Parameter<MethodType>` 与 `ReturnType<MethodType>`，再通过 `MethodSignature::new(false, ret_type, params)` 组装出合法的 CIL 签名。

### 3. 未赋值变量读取的语义一致性（语义陷阱 #10）

- **现象**：在 CIL 规范中，`.locals init` 会把所有值类型变量清零（整数默认为 0）。但在 Python 中，读取尚未赋值的局部变量会抛出 `UnboundLocalError`。若直接放行，会导致原本在 Python 会报错的程序在 RyuPy 中能运行且输出了错误的 `0`。
- **解决**：在 MIR 构建期引入确定赋值分析（Definite Assignment），在求值表达式时检查局部变量是否已在当前顺序流中被赋初值；若未赋值则立即产生 `E0301` 诊断阻断编译，坚持「要么与 CPython 一致，要么在编译期报错」的原则。

## 学到的概念

- **两遍降级与前向引用**：在 AST 降级到 HIR 时，第一遍仅提取函数名与签名存入符号表，第二遍降级函数体，自然解耦了函数定义的先后顺序。
- **单态并查集推导（Hindley-Milner 局部化）**：在 Phase 1 局部变量单态的约束下，并查集是一种非常直观、高效的等价类划分方法，配合毒化类型可以实现零连锁报错的良好编译器体验。
- **CLI 静态类托管布局**：Python 模块中的顶层函数在 .NET 中非常契合静态类（`abstract sealed`）的静态方法布局，既保持了轻量级直接调用，又符合托管运行时的验证要求。

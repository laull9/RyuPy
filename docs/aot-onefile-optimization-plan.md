# 单文件启动优化：设计复核与实施边界

状态：规划，尚无产品改动或收益验收。现行ADR-0188独占临时解包、父进程等候和退出清理继续生效。
2026-11-15异构设计完成后，主代理对照Program.cs、Payload.cs及onefile_archive.rs复核如下。

## 可保留的机制

构建期随机发布ID、私有用户根、并发独占构建、同卷暂存原子发布和完成标记可作为缓存基础。
普通文件不计算hash；完成标记证明一次发布已完成，真实运行及必要布局用于验收。
缓存身份元数据需明确包含入口路径/长度/版本，不能声称现行归档头已有这些独立快路信息。
完整CPython、扩展、资源和许可证必须随包保留，native与provider分别测试。

## 必须修正的设计

1. 默认共享只读载荷会改变合法的资源就地写入、按__file__写配置等行为；将其称为非合规应用无法消除语义变化。
   现有默认隔离写入合同继续保留。共享执行镜像只能作为显式选择，或通过每次独占可写克隆保留原合同。
2. Unix可rename/unlink运行中库的目录，rename成功和7天时间戳均不能证明无人运行；
   后续延迟dlopen仍依赖目录内容。清理必须使用可验证的运行租约，或只在显式确认无运行实例时执行。
   10分钟年龄也不能证明解包进程已死亡；同发布的独占锁与工作目录所有权应控制残留清理。
3. 发布缓存应有磁盘预算和安全回收协议。只按年龄在miss时扫描所有版本仍可能无限增长，
   也违反启动不全扫的目标；需要维护有界索引/预算及非启动快路的回收入口。
4. Unix exec可消除等候父进程，但必须先定义租约跨exec、信号处理重置与参数UTF8/指针数组ABI。
   string[]声明不能直接假定形成正确NULL终止argv。exec失败应有确定诊断且释放本轮资源。
5. 进程峰值RSS高水位跨exec可能保留解包阶段峰值；不能将exec后的ru_maxrss直接称为仅业务进程内存。
   独立观测当前RSS、整次峰值及进程树同时峰值。
6. 当前没有分层计时，不能断言422ms中绝大部分属于哪一阶段；解包、chmod、启动与删除分别测量后归因。
   常量2倍空间预检既不能保证后续写入成功，也可能拒绝实际足够空间，写入错误与安全清理仍是必要合同。
7. 不承诺跨平台亚毫秒快路、零RSS或完全保真信号。Windows Ctrl+C杀进程树沿旧行为验证，
   与CPython可运行finally的差异必须单列；不能以相同退出码代替行为相同。

在确定运行租约、预算回收、权限/路径边界和回退规则后登记ADR，再实施一个可独立验收的完整路径。

验收须包括并发冷/热运行、中断/损坏/只读目录、资源写入隔离、延迟原生扩展导入、
参数/环境/三流/退出及信号副作用、全输入删除后的单文件搬迁，以及native/provider两种真实载荷。

## 原 runner 的观察范围

用户联合分发 runner 同步等待 CP/JIT/Native 各进程完成，保存退出码及 stdout/stderr 原流；通过断言核对 CP 输出、provider 来源、静态闭包、实际 schema9 清单、资源与模块位置声明。它还观察缺资源构建失败时旧包文件字节不变，删除源码/build/JIT 树后在受限 PATH 下运行搬迁包，并检查删除已发布资源后的失败。这些是脚本现有检查设计，不是本整合候选已通过的结果。

同步等待进程与阶段间字节比较不构成原子文件快照、恶意并发替换防护或系统调用沙箱。原 runner 成功路径会删除部分输入与资源，不能把其成功日志当作那些已删除对象仍有完整归档证明；源码/SDK/部署字节闭集、权限和链接观察需按实际保留原件分别核验。不能用返回值中的 `passed` 代替对原流、实际清单与文件内容的核查。

## 验证边界

公开 verify 的目标仍仅为文件闭集、相对路径、size/SHA 和唯一 native 角色的内容自洽检查。完整 schema 语义、真实性、执行权限、原生依赖闭包和目标机运行兼容性不在承诺内，报告中的 `authenticity`、`runtime_compatibility`、`schema_semantics` 保持 `not_checked`。同时自洽修改文件与清单可被接受，不能当作签名认证。

后续三平台需重新核对公开构建及验包、搬迁、负例、前后字节/模式快照、工具哨兵和真实跳过记录。GitHub ZIP 本身不证明原宿主权限或链接，空 PATH 与哨兵也不证明断网或干净机器隔离。本记录不宣称整合已通过，不增加任何性能收益结论。

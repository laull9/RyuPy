# 字段驻留生成器的AOT验收

## 实现与范围

本轮实现[架构路线](aot-architecture-performance-plan.md)的G首切，取舍见
[ADR-0202](adr/0202-resident-generator-state.md)。基线产品为45bfabda；候选使用本提交的源码。
验收平台macOS arm64，CPython固定3.12.13，原始26项的源码、规模与入口均保持原样。

MIR显式声明生成器字段类型与构造操作。PC使用原生long；原MIR的整数、浮点、bool局部保持
原生字段，动态值保留原对象引用。普通恢复入口只取得载体与PC，按读写点访问长期字段；
匿名临时只在实际跨暂停时驻留。编译器统一操作数读集合，死亡值删除与暂停活跃性复用。
PyGenerator继续处理send/throw/close、重入、返回值、PEP479、异常上下文及真实来源。

原始generators的count_up及生成器表达式命中；yield from链保留旧状态机。
EH、闭包cell/env、模块状态、locals观察及trace V1均保留既有合同。
普通延迟lowering与trace V1开关已解耦。当前切片未实现动态整数计数窄化或消费者融合。

## 正确性与门禁

- 5项MIR结构测试：原始工作负载、跨yield匿名表达式、原生计数字段、复杂路径后备、非法构造诊断。
- 4项C#状态载体验证：返回值一次消费、send/throw、首次throw/close、完成清引用与固定ABI。
- 手写e2e已转正：别名、同一大整数盒、发送值、嵌套yield、重入、PEP479、旧新状态机混合消费。
- 主用例同次CP/JIT两种PIC核对退出/完整双流；NativeAOT删除源与build后，在中文空格路径、空PATH运行通过。
- NumPy2.3.5：两个生成器均确认字段工厂命中；外来整数身份、数组身份与别名写入，随包AOT删除所有输入搬迁通过。
- 函数体异常及throw注入异常：旧新AOT退出/完整stdout/stderr逐字一致；CP核对退出、stdout、末行错误。
  CP的源码echo/caret格式沿已有边界单列。
- 最终make check退出0：fmt、严格Clippy，C#3179通过/2跳过，MIR382通过/4隔离，
  cases-selftest761通过，编译e2e479通过/286忽略。

首次完整门禁发现旧结构测试固定要求MakeGenerator/数组spill；已改为检查真实owner捕获、
暂停前绑定发布与恢复后同一字段读取。旧数组证明仍由独立后备测试保留。
星号解包断言进一步要求仅最后一个跨暂停结果进入字段，前两个短命结果留在本次恢复局部。

## 计时方法

冻结旧新CLI，运行`tests/perf/aot_hotspot_pair.py`；同次CP直接执行原脚本。
每项1次预热、5次正式测量，CP/A/B与CP/B/A交错。构建与全部测试结束后独占计时；
主表无stats，分配/GC使用独立诊断轮。逐轮核对完整双流及退出，另外执行中文空格、空PATH搬迁。
原始报告与临时构建树位于仓库外；原始报告不入库。

首轮generators重点1warm7为CP113.281、旧284.045、新212.307ms，耗时减少25.3%；
分配145263520→145263392字节，RSS旧21.81、新21.75MiB。该轮属于独立首轮，
最终26项及必要追加轮的结果在下节登记。

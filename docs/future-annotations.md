# 有限延迟注解：PEP 563

`from __future__ import annotations` 是模块级语义开关，只允许位于开头连续 future 指令区（可在模块文档字符串之后）。别名不改变开关语义；导入绑定仍真实保留。各模块独立判断，不通过导入继承。

## 已实现

- 函数参数/返回值、嵌套函数、类简单字段及模块简单变量的注解保存为规范字符串；不解析类型名、不求值属性/下标/union、不捕获仅出现在注解里的外层名字。
- 语法子集：Name、Attribute、Subscript、`|`、Tuple、List、None/布尔/整数/省略号/字符串常量。基于 AST 优先级生成，而非取源码切片。
- 规范示例：`(A | B) | C` → `A | B | C`；`A | (B | C)` 保留右括号；`T[(A,)]` → `T[A,]`；`"Forward"` 的注解字符串内容是 `'Forward'`（包含引号）。
- 字符串常量首批支持 ASCII（含控制符转义）和非 ASCII 字母/数字；其余 Unicode 分类的可打印性与精确转义尚未实现，明确 E0100。浮点、复数、bytes 常量也暂不支持。
- 函数 `__annotations__`、类 `__annotations__` 沿用既有活动字典协议。装饰器收到已经设置字符串元数据的原函数，不自动复制包装器元数据。
- 模块存在任意变量/属性/下标注解时，在执行模块语句前建立一次 `__annotations__`；扫描包含未执行分支，排除函数/类的独立作用域。仅简单变量注解在可选右值赋值后，按当时的 `__annotations__` 绑定执行下标写入，支持用户重新绑定自定义 mapping，不逐条重建字典。
- 类只含括号名字注解也先建立空字典，但该名字不登记注解或 dataclass 字段。
- 函数局部注解不求值、不创建局部注解字典；其中未使用的复杂表达式也不会为了格式化而执行。局部名称绑定规则仍保留。
- 带注解的属性/下标赋值执行普通赋值，但不记录注解；没有右值时仍顺序求值目标组成部分，不读取目标值。

## 明确拒绝与边界

Call、lambda、推导式、复杂算术等注解字符串化尚未实现，发生在需保存元数据的位置时报告 E0100，保留独立 pending 验收；绝不通过执行表达式、忽略标记或原样复制源码伪装支持。没有实现 `typing.get_type_hints`、字符串前向引用求值或完整 `ast.unparse`。

普通赋值不因 future 改成注解：例如 `Alias = Literal['x']` 仍必须真实导入/调用对应 typing 对象。只有字符串化能力通过不表示 termcolor/Markdown 等项目通过。未启用 future 的既有注解行为不在本切扩展，尤其不据本节推断普通模块注解字典已经完整实现。

## 分层与成本

HIR 中单独 formatter 负责 AST → 字符串常量，类型提示降为 Runtime，避免将未解析注解变成静态布局或参数限制。闭包分析排除延迟注解名称。模块注解写入用既有赋值/下标和控制流节点表达，不增加后端 Python 语义、新运行时 ABI 或运行时解析器。

字符串规范化只发生在编译期；运行时仍需按定义位置创建元数据字典，保持函数重新定义与可变字典语义。延迟注解不提供免费静态特化，Runtime 提示可能失去原静态路径；未作未经测量的性能改善声明。

## 证据

- `annotation_format`、`annotation_tests`：优先级/引号、未知名称、闭包不捕获、dead branch setup、复杂格式 E0100。
- `m3_7_future_annotations.py`、`m3_7_future_annotations_scope.py`：固定 CPython 3.12.13 差分通过；`m3_7_future_annotations_setup.py` 补充非简单目标初始化验收。
- `m3_7_future_annotations_complex_pending.py`：保持 pending，防止把复杂表达式假称已支持。
- driver `m3_7_future_diagnostics`：复杂延迟注解、FLUFL、未知指令及非法位置仍保留拒绝快照。

# AOT PIC 条目按需分页候选

2026-11-15：四张核心缓存表已完成静态实现和主代理首轮修订。当前仍由 Speed 测量代理独占构建计时，PIC 尚未编译、测试或测量收益。

## 范围与设计

`CallEntries`、`GetAttrEntries`、`SetAttrEntries`、`MethodEntries` 各保留 16384 个条目的逻辑容量。
新增内部 `PagedEntries<T> where T : struct`，固定256项一页、64页；初始化只建立根指针数组，访问时按需分配条目数组。
每站点四个连续槽位始终位于同一数组页。`ref` 索引器保留原地结构体读写，现有淘汰、类版本和失效算法继续使用原代码。

页大小固定使热路使用常量位移和掩码。容量构造计算先减一再除，避免先执行容量加法的整数溢出。
`CallVictims` 等轮转表、`ArgScratch`、`PreparedScratch`、`GetterScratch` 与 `SuperEntries` 保持原布局，已有反射契约保留。

## 生命周期与并发

页面一旦发布便持续保留，已返回的托管引用在整个存储生命周期内有效。本轮不新增重置或回收页面接口。
读取通过 `Volatile.Read` 获取页面，缺页慢路复查后分配候选数组，以 `Interlocked.CompareExchange` 发布。
竞争失败方返回已经发布的胜出页面，之后各槽写入落在同一数组。竞争期间可能分配多个临时数组；诊断计数只统计已发布页面。

CAS 只保证页面引用发布。条目字段同步仍遵循现有 PIC 的约束，本轮没有建立更强的并发执行保证。
在 ARM 平台 acquire 读取与额外寻址有成本，实际速度取决于 NativeAOT 生成代码和调用点分布。
名义托管分配量与操作系统峰值 RSS 分别测量。

## 源码测试

新增 `PyPicPagedStorageTests.cs`：

- `ref` 就地修改和整项替换后重读一致，未访问页保持未发布。
- 写读全部4096站点的四个槽位，检查实际触及的页数及255/256边界隔离。
- 负数、末端和越界索引；非法容量受控抛出异常。
- 并发访问同一页不同槽位，检查发布页数和全部写入结果；不从计数推导临时分配次数。
- 在63、64和4095站点执行真实调用、方法替换、属性读写、类值失效和实例属性遮蔽，覆盖四张表的页边界及末端。

既有 `PyPicTests`、属性/方法与 trace 重入套件也须通过。公共运行时 ABI 不新增类型或方法。

# 三项性能候选的 dev 集成

本批基于固定 dev `81758bb477729aee4636f2ca6d6b0815b949849a`，保留用户的原生库接入工作。

- list：采用已验的切片结果所有权转移，减少一次复制；不启用分段背板原型。
- 生成器：合入 `cfcb69dc` 的显式 Cargo feature 候选，默认关闭。
- records：合入 `d45aa0e2` 的 feature 与 CLI 双重选择候选，默认关闭，诊断另隔离。

三个独立实验的成功不能替代组合提交验收。组合验证须覆盖默认与同时启用构建、
完整检查、固定 CPython 的真实 JIT/AOT 输出及搬迁。固定 dev 的 ABI 保留并精确新增
11 项：生成器 8、records 守卫 2、探针接口 1。历史 1659 专项与 FreshProcess 的既有跳过
不能被这些验证替代。真实 DLL 比较沿用专用 `GeneratorAbiBaselineTest` 构建，但比较
集合扩展为手写组合增量，缺失、变签、重复和未知项均拒绝。

此前四轮冷进程实验显示生成器两个目标稳定受益，但并非暖态或全平台证明；
零批量发射项目的回退方向不稳定，str_concat 个别轮仍明显变慢。records 只有单微基准
六样本，空 dict 自定义 hash 次数和 dict 子类差异仍单列。故不将合入 dev 等同于默认启用。

组合前完整私有备份与集成前精确远端 HEAD 检查必须保留，更新 dev 采用并发保护，
禁止覆盖后续用户提交。编译出的 IR、报告、二进制不进入源码 Git。

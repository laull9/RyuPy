# ADR-0030：工具协议、类型元数据与有守卫的数据类构造

状态：已接受。M3.6 原始验收、守卫优化实测与聚合门禁通过。

## 目标与范围

保持原 M3.6 六项验收：常用容器与惰性工具、函数包装与缓存、数据类字段行为、
类型元数据和生成器上下文清理。逐 API 范围分别见 [容器表](../stdlib-collections.md)、
[函数工具表](../stdlib-functional.md)、[元数据表](../stdlib-metadata.md)。
导入成功和若干 API 测试不改变固定 20 项目的分母，也不代表整个模块兼容。

## 原生协议桥

明确区分可调用、非数据描述符与受支持的 dict 子类包装，不能把所有原生对象都绑定 self，
也不能把任意 Mapping 误当原生字典。Counter/defaultdict 的 dict 祖先行为接入复制、
关键字展开与 JSON；JSON 的循环检测仍使用包装对象身份。可变包装不可哈希。
deque 保持有界消费及迭代失效，chain/islice/repeat 保持惰性边界和异常后的可恢复/耗尽状态。
未开放的 ABC 注册、内建类型任意继承、Hashable 的完整隐式 hash 槽语义仍独立登记。

## 包装、缓存与上下文

partial 保存活的 keywords 字典，不当作方法描述符；LRU wrapper 则按描述符绑定方法。
缓存键按类型与关键字顺序构造，一次调用仅计算一次键 hash；淘汰不再次执行用户 hash。
函数体在缓存锁外运行，相等比较重入修改缓存后必须重新检查版本，不能沿失效链表继续操作。
缓存持有参数与结果强引用到淘汰/clear，不伪造弱引用释放语义。
contextmanager 的装饰器路径显式建立、恢复异常上下文；throw/close/非法额外 yield 都保留异常身份。
`raise existing from cause` 不复制异常；from None 保留隐式上下文但设置独立报告抑制标志。

## 数据类正确性默认路径

旧 CLR 静态数据类构造/字段直读很快，但不能完整表达 Python 类替换、默认值/factory、
描述符和生成 eq；现有基准中两个同字段实例的 eq 返回 False，不能拿该错误结果作为正确实现的等值性能基线。
默认使用统一 PyClass/PyInstance 表示，注解保存定义时求值的真实对象，字段按顺序初始化。
保留旧静态实现供后续可证明安全的特化，不通过丢弃类身份与描述符来追回速度。

仅接受正确但极慢的默认路径不符合项目性能目标，因此实施守卫构造计划：
生成 __init__ 的精确对象身份、全局类版本、property 与装饰时 post_init 规则决定是否可走快路。
首批快路只处理全部 init 字段、无 factory、完整位置参数；预登记槽直接写入同一种 PyInstance。
关键字、缺参/过参、工厂及守卫失效继续走原绑定器和生成初始化函数，错误与副作用不能被优化吞掉。
frozen 只允许内部初始化写入，外部赋值仍拒绝。

## 编译器局部优化

MIR 在生成器降级与 CFG 简化后进行固定点死值消除，仅移除全程序当前函数内无人读取的 Use/Box 赋值。
读取根包含全部操作数、嵌套数组、终结指令与异常处理局部；不删除调用、Unbox、字段读取或运算，
因为这些可能抛错或调用用户协议。保留局部声明；这是无副作用值传递优化，而非假设注解永远成立。
该优化已在字段读取基准中消除每轮未使用的循环变量装箱，不能据此宣称动态属性与算术已达到静态速度。

## 延迟装箱累加器实验

在上述改进后，实际编译字段循环仍每轮分配一个 24 B 的整数盒，继续优化而不是把残余退化简单列为可接受。
新增内部 Create/Add/Value ABI，单次函数调用只创建一个 holder，保存精确 long 或原动态对象。
仅在入口 preheader、单 body/latch、唯一出口的自然循环且无 EH / cell / generator / env 时匹配；
循环内该局部只能参与唯一的 `+=` 自读/写，不能在 rhs、调用、比较、容器、别名或其它块中被观察。
复杂循环和已有别名观察继续执行原路径；优化不是按函数名或基准源码硬编码。

long+long 无溢出时只更新原生字段并清除旧物化缓存；溢出、bool/float/用户对象走原完整 inplace 协议，
运算成功后才提交状态，保留用户方法返回对象身份。出口 Value 延迟物化且同版本复用同一盒；
零轮保留原初值身份。一次 holder 本身仍有分配成本，不能宣传函数零分配。
结构守卫、真实差分与最终聚合门禁通过，只读审查未发现正确性阻断；该保守匹配路径默认启用。

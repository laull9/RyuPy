# ADR-0013：动态热路径去分配，保留装箱表示

- 状态：已接受
- 日期：2026-10-31
- 关联里程碑：M2.11
- 补充：[ADR-0012](0012-bounded-dynamic-pic.md)

## 背景

ADR-0010 确定动态值使用装箱 `object`。M2.9 的 PIC 只解决了「分派」的一部分：
动态基准仍然比 CPython 慢约 5 倍。profile 与微基准显示，主要成本不是 `switch`，而是**每次操作
的分配与多余调用帧**：

- `PyBinder.Bind` 对简单位置调用也分配 `bound` / `filled` / 位置槽列表；
- 每个动态调用都构造三个 `object[]`（位置、关键字名、关键字值），即使后两个为空；
- 循环里的数值字面量每次 `box`；
- 方法调用每次保存/恢复 `super()` 上下文，即使函数根本不调用 `super`；
- 实例属性存放在 `Dictionary<string, object?>`，读写都要做字符串哈希与字典查找；
- `PyOps.CallMethod` / `CallValue` 即使没有 `*` / `**` 也走 `FlattenArgs` 的复制路径。

这些都不是语义要求，而是实现方式带来的固定开销。

## 决定

保持「动态值 = 装箱 object」不变，先消除上述分配与调用帧：

1. **小参数动态调用**：MIR 新增 `DynCallValue` / `DynCallMethod`（纯位置、≤3 个实参）。
   codegen 调用 `PyPic.CallValueN` / `CallMethodN`，运行时按调用点复用参数数组。
2. **thunk 快路径**：简单位置签名且实参个数正好时，生成的 thunk 直接读取 `args[i]` 并调用
   静态方法；只有参数不匹配或含关键字时才进入 `PyBinder.Bind`。
3. **Bind 快路径**：只有普通位置参数且无关键字时，按顺序填参数；实参正好占满时直接复用
   调用方数组（只读）。
4. **数值字面量池**：codegen 收集 `Box` 的数值常量，模块初始化时装箱一次并存入静态字段；
   循环里直接读字段。
5. **实例属性槽位**：`PyClass` 维护「属性名 → 槽位」表，`PyInstance` 用值数组存放属性。
   删除写成未赋值哨兵；新增槽位让类版本递增。
6. **属性 PIC**：`DynGetAttr` / `SetAttr` 带调用点编号；命中时直接读写实例槽位，
   类版本变化或槽位未赋值时回退通用路径。
7. **方法调用 PIC 扩展**：缓存绑定方法、类版本与「方法名对应的实例槽位」；同名实例属性
   只有该槽位已赋值时才可能遮蔽，检查是 O(1)。函数不调用 `super()` 时跳过方法上下文。
8. **数值快路径**：`long` 与 `long` 的 `+ - *` 直接走 `PyInt.*I64`，跳过形状分类与缓存查找；
   溢出仍升级 BigInteger。
9. **实参展开快路径**：没有 `*` / `**` 时直接复用位置数组；只有关键字时只转换名字数组。

## 实测

固定输入与命令见 `tests/run_benchmarks.py`（macOS arm64、.NET 10.0.403、Release、
CPython 3.13.13，1 次预热 + 5 次中位数）：

| 基准 | 输入 | CPython (ms) | 改造前 RyuPy (ms) | 改造后 RyuPy (ms) |
| --- | --- | ---: | ---: | ---: |
| dynamic | 300 万动态加法 + 200 万方法调用 | 162 | 792 | 196 |
| dynamic（PIC 关闭） | 同上 | 162 | 819 | 386 |
| add_only | 300 万次 `add(total, 1)` | 102 | 463 | 98 |
| call_only | 300 万次动态函数调用 | 80 | 347 | 67 |
| method_empty | 200 万次空方法调用 | 50 | 153 | 68 |
| method_add | 200 万次 `self.v += 1` | 67 | 425 | 132 |
| fib | `fib_rec(30)` + 20 万次 `fib_iter(90)` | 288 | 154 | 155 |
| mandelbrot | 240×120、1000 次上限 | 1237 | 274 | 266 |
| containers | 20 万 append + 10 万字典读写 + 5 万字符串拼接 | 33 | — | 176 |

动态基准整体快约 4 倍，从 CPython 的 0.20x 提升到 0.80x；纯动态调用已快于 CPython。
在固定 CPython 3.12.13 的 `make bench` 中，dynamic 为 196 ms（CPython 192 ms，0.98x），
PIC 关闭仍为 384 ms。
静态路径（fib / mandelbrot）不受影响。字符串拼接仍明显落后：`.NET string` 不可变，
CPython 在引用计数为 1 时可以原地扩容，本实现没有等价的表示，暂不为此改变动态字符串 ABI。

## 后果

- 动态值仍是 `object`，语义与偏差登记不变；优化只减少分配与调用帧。
- 调用点参数数组是**每站点复用**的只读数组。被调函数只读取它（`*args` / `**kwargs` 会复制），
  因此递归与重入安全；运行时新增路径若持有该数组，必须复制。
- 实例槽位按类增长，只追加不回收；新增属性名会让类版本递增并失效方法 / 属性 PIC。
  这与 CPython 的 key-sharing dict 类似，长期运行下内存随「不同属性名数量」增长，而不是随实例数增长。
- 字面量池共享装箱对象；Python 数值不可变，`id()` 本来就是实现细节（D002）。
- `RYUPY_PIC=0` 会关闭 PIC 的快速入口（包括数值快路径），保留完整通用路径，便于 A/B 对照。

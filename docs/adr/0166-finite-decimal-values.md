# ADR-0166：有限精确 Decimal 值与共享有理数哈希

- 状态：独立竖切实施中，尚未验收
- 日期：2026-11-12

## 选择与真实需求

真实 toml 的编码器导入 Decimal，并以真实类型对象作为值分派键；数值输出
实际调用空格式协议。只加一个同名类可使不含 Decimal 值的入口通过，却无法
证明数值语义，因此禁止以占位类或项目特判绕过依赖。

采用不可变的符号、任意精度整数系数与十进制指数；保留负零和显示尺度，
不以 double 或 .NET decimal 存储。有限值的构造、str/repr/空格式、真假值、
比较与哈希构成一个完整值竖切。既有 native 对象协议足够时复用该协议，
不新增编译器特判或公开运行时 ABI。

巨大指数的科学计数表示、比较与哈希不物化十的幂；比较调整指数和有效数字，
哈希使用模幂。有效输入仍受真实 Python Decimal 的有限指数边界约束，
不能自行接受 CPython 已拒绝的数字。字符串解析须区分 Unicode 十进制数字、
合法下划线和空白，不将简单 ASCII 正则错误包装为完整构造语义。

## 数值一致性

Decimal 与 int/bool/有限 float 的相等、排序、哈希及字典/集合键必须一致。
现有非整数 float 的位串哈希不是 CPython 的有理数哈希，不能在新 Decimal
一侧复制该错误以凑键一致。单独修正共享有限 float 哈希，并保护旧整数、
float infinity/NaN 与容器行为。subnormal 比较使用 IEEE 精确值，不能使用
最短十进制显示文本替代数值。

这会改变部分有限 float 的显式 hash 结果，属于正确性修复；hash 不提供
跨版本持久化格式保证。性能尚无测量，不称为零成本改动。

## 有限边界与验收

首切不含 Context 精度、舍入、flags/traps、算术、quantize、非空格式、
Decimal 子类或 NaN/sNaN 等信号值。float 构造若未实现精确转换也必须明确
拒绝，不能偷用显示字符串近似。非法字符串在 CPython 中是 InvalidOperation；
若本切未实现 decimal 异常层，明确 NotImplementedError 而非伪称 ValueError
兼容。域外失败分别记录，不计正合同通过。

除通用双 PIC 合同、旧数值与容器回归、完整 check 和真实 Native 保护外，
必须执行原 toml 入口、内联表扩展与实际 Decimal 值编码探针。后者包括尾零、
超出 28 位精度、负零和科学计数；导入成功或没有 Decimal 值的入口不能替代。

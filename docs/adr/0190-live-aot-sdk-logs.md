# ADR0190：AOT SDK 实时日志与有界阶段反馈

状态：独立实现候选，真实应用与完整回归待验。

## 问题与选择

真实两应用构建中前端仅约44/425ms，总构建约12/12.7秒，ILC占约7.4/8.8秒
（历史同机默认配置证据，不外推当前树性能）。现有 `--diagnostic-stages` 却在
`output-write` 后停止，`Command::output()` 直到SDK结束才写日志。用户最长等待区间
无阶段提示，进程被外部终止时父进程内存中的SDK原流不能留存。

先解决真实等待和失败排查体验，不用未经完整身份建模的缓存换取表面速度。COFF时间、
宿主名、源路径、SDK/响应文件/环境等仍影响构建；源码mtime或上轮成功不足以决定复用。

## 决定

在本轮独占工作根中以 `create_new` 创建 `publish.stdout.log` 与 `publish.stderr.log`，
SDK双流直接重定向至文件，stdin显式关闭，维持原 `output()` 的非交互合同。不引入shell、
双pipe读线程、全局环境修改或新的外部进程。两日志继续位于build树，不进入dist。
成功不再把全部SDK原流读回父进程内存；失败及后置发布校验失败才读取同次原流构造完整诊断。
日志读取失败附带实际路径而不掩盖原SDK状态。旧文件/链接拒绝覆盖，现有owned失败留证、
低层失败清理及旧dist事务语义不变。

普通源码/项目AOT沿用 `--diagnostic-stages`：报告 `aot-sdk-publish` 的开始、SDK成功结束
或错误，以及可实时查看的转义日志路径。SDK时间独立起算（路径记录 `clock=sdk`），
不与前端elapsed直接相减，不伪造restore/ILC进度百分比。`end`仅表示SDK成功退出，
不表示后续资源/manifest/dist安装已成功。默认stderr保持静默，诊断写失败停用观察但不改变构建。
绑定构建共用实时落盘执行器，但不因此解除原CLI对绑定 `--diagnostic-stages` 的限制。

## 边界与验收

只保留SDK已经写出的字节，不保证SDK自身未flush的缓冲、不承诺机器掉电持久性或
原子并发快照。外部终止不会由本改动新增自动清理/取消子进程承诺。日志仍可能含SDK打印的
本地路径/环境信息，和原完整失败输出一样应在分享前检查。此改动不宣称编译时间或Native运行提速。

测试包含真实阻塞子进程在退出前双流已可读、stdin EOF、非零/启动失败/读取失败、已有文件与链接拒绝、
诊断关闭不取sink及路径控制字符转义。复用现两真实应用三平台公开打包/搬迁/完整性门，
在实际SDK尚运行期间保存首批日志与阶段提示，再核最终SDK日志、CP/Native原流及负例。

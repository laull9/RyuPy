# ADR-0165：原生布局提供者与完整 C3 分离，词法类沿私有事务创建

- 状态：设计与实施中，尚未验收
- 日期：2026-11-12

## 问题

真实 toml 0.10.2 的内联表工厂在方法中以动态字典类和普通标记类组成多继承。
现有普通 C3 只保存 PyClass 节点，词法类事务只保存一个普通父类；简单取消
多基守卫，或把 dict 方法放在普通查找末尾，都会得到表面能构造却顺序错误的对象。
例如 `C(dict, Mixin)` 与 `C(Mixin, dict)` 的方法优先级不同，二者的物理布局
却都来自 dict。项目名称、导入路径和类名不能成为语义选择条件。

## 决策

本竖切分开三项权威，不引入第二套项目专用对象模型：

1. 完整 C3 保存真实普通类与原生 dict/object 节点。属性、方法、描述符与 super
   必须依照同一顺序，不能只在反射元组中显示原生节点。
2. 布局解析独立选择兼容的原生存储提供者及 solid base。不得以首个声明父类
   决定 payload 或 `__base__`；不同用户 dict 子类可能共享同一物理布局。
   不兼容原生布局应明确拒绝，不复制两个 payload 或静默丢弃一个父类。
3. 词法类继续使用已有 `LexicalClassPrepare`/`Finish` ABI。基表达式按源码
   顺序各求值一次并冻结到 frame；类体使用私有 namespace；终结失败不能发布
   半成品或替换旧名。编译器不绕开事务直接创建公开类。

首切范围为普通类与 dict 布局的冷多继承路径。旧单继承快速路径保留；未知
元类、创建 hooks、其它原生布局和任意 slots 组合不因本切自动开放。
如实施发现需扩大公开 ABI 或语义域，先补充设计和精确合同，不顺手放宽守卫。

## AOT 与验证

本切不宣称 Native AOT 支持 MI。确定的词法多基在发射前明确拒绝，原有
零/单基 Native 能力及动态单基遇实际 MI 的运行时拒绝继续保留。

验收必须同时包含 CPython 3.12.13 合同、双 PIC JIT、旧 Native 保护、完整
make check、固定项目逐 ID 保护，以及未改入口的真实 toml 运行。
额外真实探针验证内联表读写往返、自定义 dict 子类、工厂每次新类身份；它
不增加固定 20 项分母，也不能替代原入口。原生节点方法顺序、super 接收者、
描述符绑定、类修改后的查找失效和失败发布都必须实测。

性能尚未测量，不能把冷路径设计当成零成本证明。

## 当前实现与审查修正

新 dict 冷族保存含真实原生节点的完整 C3，普通类投影不作为 native lookup
权威。内部 resolution 保留真实 owner 与原始描述符；既有公开 TryLookup
签名不增加伪造 owner。PyDictInstance 本来继承 PyInstance，故必须显式将
此冷族从旧 PIC 快路分流，不能假定接收者类型会自然避开缓存。

类元数据 `__slots__` 的晚改不等于已分配存储改变。原先空 slots 以及原先
没有 slots 的已完成普通祖先，都按冻结布局判断；仅新类正文的真实 slots
声明参与本次布局决议。这项准入只作用于新 dict+C3 祖先验证，不顺带放宽
旧普通词法类的协议守卫。object.__str__ 使用原生描述符原有绑定桥，不能按
名称重造一个行为不同的通用 object 方法。

完整 C# 已通过 2949 项、保留 2 项既有条件跳过；结构合同与独立反例双 PIC
仍需在最终源码再次合并验收。真实 toml 已越过词法多基编译拒绝，但下一
依赖为未实现的 decimal 模块，原入口与扩展探针当前均未通过；不计项目晋升，
不改真实包源码或用占位 Decimal 类绕过导入。

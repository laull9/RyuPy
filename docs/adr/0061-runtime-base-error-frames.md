# ADR-0061：动态基类冷拒绝保留现场帧

状态：有限诊断修复本地验收通过，尚未发布。

## 真实问题

2026-11-03在未发布optparse候选3e6e10c上，对锁定pyfiglet1.0.2的原固定入口
仅执行一次CP参考、编译、JIT。退出码0/0/1，无超时；首失败为普通运行时基类守卫的
NotImplementedError，原stderr没有Python帧。官方572源文件、原入口、候选产物和双流
已独立核验。本轮不增加项目通过数，也不代表公开main。

源码的动态str基类只是高度相关的静态线索。无帧日志不能单独确定哪一个类定义抛出，
不能据猜测直接扩张内建布局或元类能力。

## 有限方案

只在PyRuntimeBases自己的Unsupported冷错误工厂调用PrepareRaise，保留原异常类型、
消息和两处拒绝条件。成功路径、基值求值次数、普通类身份、MIR和ABI不改；不加广泛catch。
现有类定义lowering已经维护帧与行号，该修捕获当时真实栈，不伪造类名或指定源码行。
复杂基值表达式可能更新当前行，不能泛称所有错误必定位到class关键字行。

专项保旧四项C#，补冷拒绝现场帧/context与重复Prepare身份；源测试保完整错误链、
类体不执行及真实基值求值次数。CP允许而本实现暂拒的str派生不能改成CP也应失败。
完成本地门禁和恢复备份后，才对同一原项目入口作单次限时编译与JIT诊断。

不实现str派生、不扩元类，不改项目源码，不运行AOT、性能或项目矩阵。

## 首次验证记录

C#原4加新2项通过。driver首轮3/4：新用例实际外层8行、class11行与完整消息均正确，
但手写Ryu-only期望在链连接语后多一空行。该差异属于已有终端格式，不扩改通用renderer；
先独立核既有代码再精确修此预期，不能用删帧或宽松contains掩盖。
CP合法str派生参考已单次exit0；不计Ryu支持或项目通过。

上述手写预期经独立审按现renderer精确修一处LF，driver第二轮4/4通过，仍全文byte
比较而非归一化或contains。正常完整门禁首轮通过：728项C#、228项CP基线、202项e2e及30项原ignored，
fmt/严格clippy/workspace全绿。该门禁终态时尚未执行新候选项目诊断，后续单次记录见下节。

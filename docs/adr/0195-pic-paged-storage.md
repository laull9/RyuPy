# ADR-0195：PIC 核心条目的固定容量按需分页

- 状态：已接受，默认启用
- 日期：2026-11-15
- 关联：ADR-0182、ADR-0193

## 背景

PIC四张核心表的固定大数组让稀疏调用点程序承担未使用槽位的托管分配。
运行速度优先，减少分配必须结合真实墙钟和峰值RSS判断，名义数组尺寸只用于设计估算。

## 决定

内部 `PagedEntries<T>` 采用固定256条目一页、固定总容量16384；按访问惰性分配，
同一站点四槽不跨页，索引器返回托管引用。页面发布后持续保留，不增加回收/重置接口。
页大小使用常量，使热路以固定位移和掩码寻址。

页面引用以acquire读取和CAS发布；竞争失败方使用胜出页。并发首次访问可能分配临时页。
该机制只保证页引用发布，缓存条目字段及scratch的既有同步约束保留。
轮转淘汰、类版本失效、公开ABI、scratch及SuperEntries布局保留。

## 取舍

增加二级寻址、缺页分支和acquire读取，换取按需分配。总容量有界，全站点使用时增加页头和根数组开销。
峰值RSS由宿主分配器/GC和实际访问决定；需要同源AOT对照确认收益，不能由结构体尺寸直接推算。

## 验收

跨页/末端索引、ref持久修改、并发页发布、方法替换和属性遮蔽定向测试通过。
固定26项AOT对照采用冻结旧CLI与分页候选CLI，1warm5交替采样，CPython同次双流校验；
统计轮独立，每例发布目录搬迁后空PATH执行。完整26项及6项重点复测通过，make check退出0：C#3125通过/2跳过，MIR359通过/4忽略，编译e2e469通过/284忽略。见PIC专项文档。

主代理接受实际取舍：完整对照整体CP/Ryu几何平均1.0895×→1.1143×，部分容器/推导式RSS降低；重点复测strings约4.1%、generators约2.8%耗时增加。上述局部退化明确保留，下一竖切继续优化，逐项速度/内存目标持续推进。

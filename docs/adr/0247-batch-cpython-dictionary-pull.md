# ADR-0247：批量拉回跨域同步字典

- 日期：2026-11-19。

ExplorerPro 启动分段测量把进程初始化、Qt 导入、窗口构造、`show()` 和首窗暴露分开。
同一精简 `.app` 产品的一组定向对照，首窗从 27.2 秒降到 20.0 秒；两轮同次原版
CPython 分别为 9.5、9.1 秒。发布构建不计入这些时长，没有把单组视作普遍性能保证。
优化后构造约 5.2 秒，`show()` 约 8.7 秒，仍需排查窗口未显示前的跨域工作。

既有 `PullContainer` 先在 CPython 分配键列表和元组，再为每一项跨 ABI 取键、重查键值。
新 shim 在持 GIL 的单次调用中以 `PyDict_Next` 保存精确字典的顺序和原始身份，每槽
交付一个 owned 引用；托管端逐项转换，异常时释放未消费项。快照不执行映射的用户钩子，
不改变同步边界、键资格、别名或容器写回时机。版本未知时也不取解释器私有字典字段。
仍逐次读完整快照，不宣称消除同步成本。

证据位于 `~/.cache/ryupy/validation/explorerpro-products/`：
`20261119T020155.157496Z/`（批量化前同配方）与 `20261119T020343.150076Z/`（批量化后）。
另有 `20261119T020537.411956Z/startup-sample.log`，主线程在 Qt `show()` 的
递归显示回调里出现 CPython `PyDict_Keys` 和旧 shim 调用；这轮带采样，不计入对照。
固定 3.12.13 和 3.13.3 的同步字典/参数桥输入共八个 JIT 与目录 NativeAOT 搬迁通过。
记录 `stock-module-namespaces/20261119T020811.191119Z.json` 与
`stock-module-namespaces/20261119T021146.802774Z.json`。

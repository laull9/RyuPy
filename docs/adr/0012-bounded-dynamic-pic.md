# ADR-0012：动态运算 / 调用采用有界 PIC，命中才走快路径

- 状态：已接受
- 日期：2026-10-31
- 关联里程碑：M2.9

## 背景

ADR-0010 把动态值定为「装箱 `object` + `PyOps` 统一入口」。正确性优先的实现里，每个
动态 `a + b` 都要做魔术方法探测、整数 / 浮点分类和操作码分支；每个动态调用都要展开实参数组、
按可调用类型分派；每个 `obj.method()` 还要做一次类属性查找并分配绑定方法。热点循环里这些
开销与真正的计算无关。

M2.9 要求评估动态运算 / 调用的内联缓存（PIC），但明确允许「收益不足时保持关闭」。
因此需要先固定实现边界，再用实测决定默认值。

## 考虑的方案

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| A. 不做缓存，继续走 `PyOps` 通用入口 | 实现最简单，语义一目了然 | 每次调用重复类型判断与绑定方法分配 |
| B. 全局类型缓存（按操作数运行时类型 / 类版本做键） | 不需要给调用点编号 | 无法利用「同一调用点形状稳定」这一事实；键计算本身接近一次完整分派 |
| C. 每个调用点有界 PIC（本 ADR） | 只校验少量形状即可跳过通用分派；失效点明确 | codegen 需要分配调用点编号；缓存条目要携带失效版本 |
| D. 无界缓存 / 按对象缓存 | 命中率最高 | 长期运行内存无界；持有实例会造成泄漏，违反模块与容器生命周期要求 |

选 C。A 太慢，B 收益不明显，D 与长期运行要求冲突。

## 决定

1. codegen 在生成动态运算 / 调用指令时分配**程序内唯一的调用点编号**，作为运行时入口的
   第一个实参；编号在函数按 arena 顺序编译时递增，不进入 MIR（MIR 保持与后端无关）。
2. 运行时新增 `PyPic`：
   - 二元运算缓存键是 `(操作码, 左形状, 右形状)`，只缓存整数、浮点、布尔、字符串、
     BigInteger 这些可以确定走数值 / 字符串快路径的形状；
   - 任意可调用值缓存保存「上一次的对象引用 + 可调用种类」，引用相同才直接调用；
   - 方法调用缓存保存类、类全局版本、实例属性版本与解析出的函数；任一版本变化即未命中，
     重新走属性协议；模块属性**不缓存**，保证模块重绑定立即可见。
3. 全局最多 4096 个调用点，每个调用点 2 条条目；站点越界或条目不再命中时直接调用
   `PyOps` 通用入口，不抛错、不改变语义。
4. `RYUPY_PIC=0` 关闭整个 PIC，用于 A/B 对照与问题定位。

## 实测

固定输入与命令见 `tests/run_benchmarks.py`（macOS arm64、.NET 10.0.403、Release）：

| 基准 | CPython 3.13 (ms) | RyuPy PIC 开 (ms) | RyuPy PIC 关 (ms) |
| --- | ---: | ---: | ---: |
| 动态加法 300 万次 + 方法调用 200 万次 | 162 | 792 | 819 |
| 静态斐波那契（`fib_rec(30)` + 20 万次 `fib_iter(90)`） | 283 | 154 | 同左 |
| Mandelbrot 内部区域 240×120、1000 次上限 | 1217 | 274 | 同左 |

动态基准上 PIC 约快 3.3%；静态基准不经过 PIC。收益不大但稳定，且未命中完整回退，
因此**默认开启**。如果后续数据表明收益消失（例如运行时实现变化），把 `PyPic.Enabled`
的默认值改回关闭即可，测试与语义不变。

## 后果

- 每个动态调用点多一个 `ldc.i4` 与一次数组下标检查；静态路径完全不受影响。
- 缓存容量固定，条目数不随时间增长；方法缓存不持有实例，只持有类与函数。
- 失效依赖已有的类全局版本与实例属性版本；模块属性不做缓存，避免为模块再引入一套版本机制。
- 缓存只优化性能。任何未命中都会执行与关闭 PIC 时相同的通用路径，因此差分用例可以通过
  `RYUPY_PIC=0/1` 对照。

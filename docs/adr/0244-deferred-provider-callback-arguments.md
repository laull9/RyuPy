# ADR-0244：外部回调未读参数按需物化

- 日期：2026-11-19。
- 状态：限定显式 stock 模块命名空间；两版通用产品与三形态真实 Cocoa 最小门通过。

## 问题

CPython 原生回调的位置元组已在当前调用中持有参数，旧桥仍立即为每个槽生成托管值，
使未读的原生包装也可能活到 CLR 回收。一些扩展在原生构造期间会发布临时基类包装。
保留该包装会改变稍后得到的真实派生类型；ExplorerPro 菜单构造和独立 Cocoa 对照
均观察到此问题。不能按扩展或类型名特判，也不能靠强制 GC 恢复行为。

## 决定

- MIR 仅为显式 provider namespace 中、具有真实 owned context 的通用 `object` 位置参数
  选用此 ABI；typed、旧函数、隐藏 owner/cell 环境参数和变长签名不接受借值。
- CIL 在所有实际形参读取点发射同一中性 `Read` 操作；写回形参、未执行分支和 thunk
  绑定不触发读取。读取包括赋给局部、返回、捕获到 cell、放入容器或跨暂停保存；
  首次读取获得正常 owned 值，之后复用该值。普通传入对象原样通过。
- provider 只对已登记的函数、精确位置元组、形参数相等且无关键字的调用借用槽。
  外部方法首参保持立即转换，构造接收者和绑定协议不变。缺省绑定、关键字和不具备
  新 ABI 的代理仍走原路径。借用仅在拥有 GIL 的同线程同步回调内有效，异常退出也立即失效。

这不是完整的引用计数模拟：读取过的值仍可能由托管 GC 延后释放。被保存的值必须拥有
独立生命周期，不能在回调结束后撤销。代价是候选 ABI 的形参读点多一次轻量判别，
且准入回调需要建立借值标记；旧静态与普通 provider 产品不发射新读点。

## 验收

- PE 检查真实参数读点和工厂同时生成，旧 factory、thunk 与隐藏参数布局保持原样。
- `deferred_callbacks` 以真实 `json`、`operator` 验收按读物化、返回别名、闭包、异常和
  关键字/变长旧路径；`explorerpro_qt_wrapper_probe.py` 另验构造期未读槽与实际 QObject
  在回调返回后的容器/闭包存活。两者均不委派本地业务。
- 固定 CPython 3.12.13／3.13.3 的通用回调 JIT、目录 NativeAOT 两版四产品通过
  删除输入搬迁；生成器、定义点调用现场与同步字典回归共六个额外产品通过。
- 真实 Cocoa 固定 PySide6 6.9.2 的 JIT、目录 NativeAOT 和 OneFile 最小门 3/3 通过；
  删除输入且禁止访问原缓存后仍保正确菜单派生类型及逃逸对象。证据在
  `explorerpro-products/` 下的 `20261119T004142.040590Z/`、`20261119T004323.700438Z/`
  和 `20261119T004608.447696Z/`。[原对象隔离业务](../../tests/general_projects/github_large/README.md)
  与关闭门也分别在三形态通过。完整 `make check` 通过（3486 项 Runtime、514 项编译端到端）。
- 异常类别与退出路径通过。早期输入在模块 handler 内再次跨域读取异常文本时，
  退出后留一个 carrier/code-origin；冻结 `938f9107` 对同一输入也产生同一计数。
  不放宽现有关闭门，异常处理内再次查询的完整对象生命周期另验。

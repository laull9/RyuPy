# ADR-0062：str注解的对象身份与局部精确事实

状态：独立阶段本地专项和完整门禁通过；未发布，不代表str子类已经可用。

## 问题

Python的str注解不强制传入值一定是exact str。当前Ty::Str与CIL System.String直接对应，
注解若被当作精确表示证明，会在参数、返回或字段边界拒绝/抹去合法对象身份。
单纯将全部相关函数降为Dynamic虽然保守，却会丢掉无关数值局部与字面量的静态事实。
只对字符串子类增加广泛NotImplementedError也不是默认兼容路线。

固定CPython3.12.13一次12组设计参考已验证注解参数、返回与字段保留对象身份；
这是语言行为参考，不是RyuPy实现结果，更不增加真实项目通过数。

## 有限设计

新增注解来源的opaque对象事实，存储为object，绝不当作isinstance(str)证明。
只允许已证明的copy、return与同类合流不触发整函数降级，独立字面量和数值局部仍保
原精确类型。比较/条件等即使最终结果为Bool，也必须检查输入；任何尚未证明安全的
opaque消费沿现有整函数Dynamic回退，不能仅检查输出类型漏过静态发射。

本阶段不改变字符串payload、类继承、元类或内建消费者，不让新的字符串子类先以空壳
通过定义。若保守的返回边界使某些调用者丢失精确事实，须在验证中明确记录，不以注解
重新冒充证明，也不宣称所有字符串性能均无变化。未测量时仅报告结构事实。

## 验证约束

先独立审具体类型合流/存储/调用/coerce及所有消费点，再做有限类型/MIR结构与真实
source身份差分，最后正常完整门禁和持久恢复备份。保持既有五批兼容实现及optparse/
冷帧修复提交的独立标识；不自动推送，不运行AOT、性能或项目矩阵。

`__package__` 仍优先返回不可变registration字段，写槽后外部读回的旧偏差尚未修复。

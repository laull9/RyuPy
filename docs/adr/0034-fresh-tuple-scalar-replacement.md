# ADR-0034：新鲜临时 tuple 的有界标量替换

状态：已接受。有界规则默认启用，正确性、净收益与聚合门禁通过；不代表 M3.9 完成。

## 目标与实际 IR

直接累加局部实验表明少对象不自动更快，不能无限追逐单个微基准。
本竖切改为消除可证明没有容器身份观察的短命 tuple，直接给 JIT 普通局部拷贝，
不在 C# 底座新增另一套执行器或运行时特化对象。

现有 `a, b = b, a` 在同一 MIR 块中为：
MakeTuple → Len → UnpackCheck → 两次 GetItem → 写目标。
`return (a, b)[0]` 同样先创建 tuple 再固定索引读取。
MakeTuple 现创建元素 object[] 与 PyTuple；保留所有元素的原求值后，容器本身无用户回调。
实际 IR 探针与基线产物先于优化实现固定，不凭源代码形状假设已经命中。

## 有界证明

只考虑全函数唯一赋值的新鲜构造临时，构造与全部允许读取在同一基本块，且读取严格在构造之后。
仅接纳长度读取和已经证明、规范化后界内的固定整数下标；检查下标定义顺序和中途重写。
不通过全函数“某处存在常量赋值”猜测支配性，不把任意对象的下标协议当作常量读取。

全函数枚举操作数，包括嵌套数组和终结符，判定容器是否逃逸或被其它方式观察。
返回容器、复制别名、传入其它调用、存入容器 / 字段 / 全局、身份比较、捕获、暂停等保留原对象。
首切还保守排除 EH、生成器 / 环境 / cell，不为了扩大命中率破坏异常和跨暂停物化边界。
设置元素与改写预算；超出预算保持原代码，而非拒绝合法 Python 程序。

## 改写与语义

在原构造点逐元素保存到新的 Dynamic 局部，固定索引读取改为读取这些快照。
不能直接把 GetItem 替成原 Local：交换赋值以及后续局部重绑定会读到新值。
快照保存的是同一元素引用，不深复制元素，也不重新调用 getter、函数或 __index__。

长度读取替成确定常量；仅能证明一定成功的解包检查可删除。
不成功 / 不确定的检查保持原位置与异常，越界、切片、星号路径不借本切改变行为。
然后复用保守 DeadValues 去掉不再读取的下标 Box / Use；不扩大其可删除副作用集合。
无新 RuntimeFn 或后端指令，Python 层的安全条件全部属于 MIR。

临时容器不再分配可改变内存压力、GC 与析构时机，属于已有容量 / D001 边界；
可观察对象身份、别名、副作用顺序、异常和用户显式资源管理不得改变。

## 验收与成本

先写 pending 差分，覆盖交换、元素身份、构造点冻结、调用左到右一次、
返回 / 别名 / 传入函数的真实 tuple、生成器两次产出的同一对象，以及越界 / 解包失败前的副作用。
结构负例覆盖非支配下标、下标改写、跨块、其它读取、异常和暂停；
正例需从真实源码 dump 确认匹配，不能用未优化的程序通过差分冒称优化完成。

基准保交换、固定读取、实际逃逸对照并列，输入构造和清理在计时外。
分别量编译、进程启动、充分预热吞吐、真实分配与机器码；结果和身份必须一致。
预期消除临时数组 / PyTuple 及访问调用，但会增加局部快照与编译分析成本，
是否默认启用仍由实际收益、失败守卫和聚合门禁决定，不能只数删掉多少 MIR 指令。

## 已实现的规则与测量

当前规则最多 8 个元素，每函数按源序最多尝试 32 个候选；失败也消耗尝试预算，
不把“最多成功 32 次”误当作拒绝扫描已受限。Len 的唯一定义事实一次建表，
单遍验证后续 UnpackCheck，不以长度读取次数乘整块长度反复扫描。
只接受匿名构造临时与动态 Local 元素；其它表达形式保持原通用路径。

真实源码的交换和固定读取已经由 MIR / CIL 快照锁定命中；逃逸函数仍含 MakeTuple / GetItem。
固定 Python 差分、结构负例和完整门禁均已通过：
`/tmp/ryupy-m3_9-tuple-checkpoint.log` 中 `make runtime && make check` 整体退出 0，
422 C#、216 Python 基线、191 编译 e2e / 29 ignored，fmt / clippy / Rust / 无更新快照全绿。

两组交错配对均使用默认 holder、同一 runtime、相同输入与完整逃逸对照。
每次 20,001 轮，默认 swap 从 4.814 / 3.617 ms 降至 0.0430 / 0.0435 ms；
禁 tier 从 1.963 / 1.387 ms 降至 0.0458 / 0.0459 ms。固定读取也在两组持续获益。
这不是“真实 tuple 构造快几十倍”，而是证明中间容器不被观察后直接不构造；
不能将该微负载倍数外推到项目。

独立分配诊断中 swap 从 1,280,128 B 降至 64 B，保留最终返回 tuple；
read 从 1,280,064 B 降至 0 B；escape 仍为 1,280,088 B。
FullOpts swap 451→291 B、read 341→204 B，循环及行号更新仍存在。
逃逸函数 CIL hash、机器码体积和分配完全一致，但其计时有正负波动，原始不利样本同样保留。
这支持有界规则默认启用，不支持“所有逃逸路径精确零时间差”或整个进程零分配的主张。

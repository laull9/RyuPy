# ADR-0175：资源树与实际输出的早期相交诊断

## 问题
显式 `trees.directory: "."` 若包含本次 `.build` 或 `.dist`，可能扫描旧产物或将构建写入误视为资源变化。仅在暂存后报告集合变化太晚，也不能靠偷偷排除输出文件改变用户声明。

## 决定
高层AOT布局将自己已知的实际 `.build` / `.dist` 边界，通过临时 `ResourceRequestContext` 传给同一次模块图解析流水线。模块位置确定后，对所有资源树先统一预检，再递归展开，避免第一棵树展开错误掩盖后一棵树的输出相交。

选择树与实际生成目录相等、互为祖先时拒绝；诊断列出模块、声明目录、实际相交路径，并建议用 `-o` 迁移输出或收窄资源目录。共同输出父目录不是排除根：项目根作为 `-o`，`assets` 与 `app.build` / `app.dist` 为兄弟目录时仍合法。

已有路径先规范化以消除平台别名，尚不存在的路径通过最近存在祖先投影；比较路径组件而非字符串前缀。声明树内不跟随链接/reparse。Windows采用无损路径组件及保守大小写比较；既有来源、nofollow、内容冻结、输出所有权和最终安装校验全部保留，此诊断不替代安全校验。

不添加永久Session权限状态，不重新扫描第二张模块图。低层无输出上下文的编译/oracle入口维持原合同；真实高层构建必须传入布局边界。

## 早期边界与验证
此处“早期”是模块图解析后、资源树扫描、MIR发射、SDK调用和资源复制前。外层仍可创建自有build/attempt并记录失败日志，不承诺磁盘零写入；旧dist必须完全不变。

测试覆盖首构建 `.json` 自包含、已有dist保持、同/父/子相交、安全兄弟、平台输出别名、所有树先预检、故意不支持MIR的输入仍先命中相交，以及隔离fake SDK未调用。子进程门须核实确实运行一个测试，不接受零匹配成功。平台CI要求对应全部边界测试真实通过，随后保持原真实pyfiglet两入口Native验收；不以字符串诊断代替成功打包验证。

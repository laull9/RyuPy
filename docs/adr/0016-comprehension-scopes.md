# ADR-0016：推导式先复用独立函数作用域

- 状态：已接受（首个 list 竖切）
- 日期：2026-11-01

## 背景

推导式的循环绑定不能污染外层；其中的 lambda 捕获同一个循环 cell，且每次执行推导式有
独立环境。最左 iterable 在外层求值并取得迭代器，后续 iterable、条件和元素在内部作用域执行。
M3.0 已有共享 cell、嵌套函数、环境和动态调用，M2.4 已有通用迭代协议。

## 方案

直接内联循环可以省掉隐式函数对象与调用，但必须额外实现作用域槽位隔离、外层同名值恢复、
异常出口和逃逸 cell 的生命周期，不能把循环变量临时覆盖后恢复当成正确实现。

隐式函数可以复用已有环境传递和控制流，代价是每次执行推导式创建一个函数对象，并在需要
捕获时创建环境；内部列表增长沿用运行时 append。当前没有证明它比 CPython 更快。

## 决定

首个竖切将列表推导式登记成 `<listcomp>` 嵌套函数。隐藏位置参数 `.0` 接收已取得的迭代器，
结果存入 `.result`；源码标识符不能与它们冲突。循环、if、append、return 全部复用 HIR 节点，
MIR、codegen 不增加对 Python AST 的依赖，也不新增运行时 ABI。

每次推导式执行只创建一次隐式函数和所需环境，不在每个元素处创建它们；元素本身若为 lambda，
仍按源码逐次创建函数并共享循环 cell。模块名字继续走全局槽位。类体、异步推导式、海象表达式
暂不支持，明确报诊断；dict/set 在独立竖切接续，生成器表达式必须等状态机可用后才验收。

## 后果

优先锁定可观察作用域、闭包、异常与副作用顺序，不为消除一次调用接受语义偏差。
后续可在证明捕获和身份不可观察时内联，需保留异常路径并测量分配与稳态性能后再宣称收益。
生成器表达式将复用最左 iterable 的立即求值边界，但不能以急切列表代替惰性执行。

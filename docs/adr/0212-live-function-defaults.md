# ADR-0212：函数默认值元数据与实时参数绑定

- 日期：2026-11-16
- 状态：C2 首切实现，集成门与性能验收中
- 接续：[ADR-0208](0208-cil-execution-libpython-kernel.md)

## 决定

`PyFunction` 暴露真实 `__defaults__` tuple 与 `__kwdefaults__` dict，支持替换、删除和
字典别名修改。默认值在定义位置求值，元数据修改则从下一次参数绑定生效。
签名参数名、参数种类与函数实例可变默认值分别管理；禁止修改共享 `PySignature`。

首次访问默认值元数据时建立冷状态，保持容器及元素身份。Binder 仅在参数缺省时查询
当前默认值，普通未观察函数继续使用已有默认数组。函数实例字段布局保持原形状，
冷状态以独立默认数组为弱键，防止共享空数组混合多个函数的元数据。

完整实参继续保留原直调。缺省调用首先冻结真实callee，再按源码顺序冻结实参。
legacy普通顶层Dynamic函数、至多三个纯位置形参且缺少的尾参均有定义默认值时，
在实参完成后比较callee与对应def的已验证私有实例锚点，并检查无默认值冷反射状态。
满足守卫才从同一callee读取当前原默认数组、填充缺省槽并沿原Fn直调，尾owner仍传
该实际对象。其余路径由同一已冻结callee的Binder绑定，实参和副作用均只执行一次。

守卫使用函数对象引用身份；Body为只读且私有锚点由对应MakeFunction成功发布。
共享签名、同名函数或同一Body的重建函数对象都不能代替该身份。只读默认值也会进入
冷状态并使快路失效。嵌套Env、实例模块、状态机、关键字和宽签名继续已有绑定链。
已有默认值函数、同模块逃逸函数和类方法使用 Dynamic 参数与函数体，使修改为不同
Python 类型的默认值能进入真实函数语义。标注继续作为优化提示。

## 取舍与边界

初版全Binder方案在冻结5d36基准的26项配对中功能全部通过，但calls墙钟
93.877→115.866ms（+23.42%），分配372078056→420428832字节，全量墙钟几何
平均+1.74%，故增加上述未观察默认值的有守卫直调。新快路与普通 super 冷布局修复后的六次平衡配对中，calls 为 99.393→97.814ms（-1.59%），
分配为 372078040→372078144 B；全 26 项墙钟几何平均 +0.55%，所有单项结果见
[首轮集成验收](../cil-execution-first-slices-validation.md)，文末十二次定向配对未复现容器/字符串的持续回退。
已有反射状态仍承担Binder成本，带默认值函数的typed特化范围保持当前正确性选择。
先保证已开放的默认值更新合同，再通过跨模块封闭性证明或带守卫的双核心恢复静态快路。
收益与回退都须在固定工作负载上实测；不凭数值 helper 的结构测试推断整体性能。

跨模块的原无默认值 typed 函数仍有已复现缺口：其它模块新增不同类型默认值时可能
进入原 typed thunk 并发生类型错误。保留原始多文件 pending 用例，后续补全发布边界。
原生 `inspect.signature`、完整 code/frame 与扩展精确布局协议属于后续 C2 切片。

实现与版本、差分和测试记录见[函数默认值合同](../cil-function-defaults.md)。
产品 CPython 3.9–3.15 的版本探测、桥接 ABI 与分发合同继续保留；固定 3.12.13 oracle
用于可复现差分，多版本行为另列。

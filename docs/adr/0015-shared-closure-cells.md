# ADR-0015：共享 cell 与函数实例环境

- 状态：已接受
- 日期：2026-11-01

## 背景

M3.0 要让函数逃出外层作用域后继续读写变量。循环里的函数共享循环变量，`nonlocal`
修改也必须被其它闭包看见。复制变量当前值会破坏这些行为。

## 方案

为每种闭包生成 CLR 环境类，可以给捕获字段安排具体类型，但会增加类型、字段与构造函数的
生成逻辑。已有动态路径统一使用 object，首版暂不依赖这些特化。

共享 cell 加环境数组可以复用现有数组 ABI。代价是每次访问都要取数组槽位，外层函数也要
切到动态路径；后续可以在保留身份和别名的前提下特化。

## 决定

每个被捕获的局部变量使用一个 `object[1]` cell；每次外层函数调用创建新 cell，同一次调用
产生的闭包共享它。环境使用按 free 列表排列的 `object[]`，中间层只传递 cell 引用。
模块变量继续使用模块槽位，函数内的 `global` 会截断向外层函数的查找。

`PyCall` 第一个参数接收 `PyFunction` 实例。thunk 从该实例读取默认值和环境，绑定 Python
参数后把环境作为隐藏尾参数传入函数体。环境不参加 Python 参数计数。签名按源码定义共享；
每次执行嵌套 def 或 lambda 创建独立函数对象与默认值数组。没有捕获的函数使用 null 环境。

本作用域读取空 cell 抛 `UnboundLocalError`，自由变量读取空 cell 抛 `NameError`。
默认值在定义位置的外层作用域求值；函数体中的读取按调用时的 cell 内容求值。

## 后果

运行时没有按调用次数积累的闭包注册表。签名数量随编译进程序的函数定义数量增长；
cell 数量随仍可达的外层调用增长，每个环境长度由该函数的 free 数量确定。
默认值数组长度由参数数量确定。函数、环境与递归 cell 形成的引用环交给 CLR GC 回收，
不承诺 CPython refcount 的即时释放时机。持有闭包会保留它引用的 cell 和其中的对象。

未捕获变量和原有静态直调继续使用原来的路径。包含嵌套函数或读取 free 的函数当前走动态
模式；性能证据见 M3.0 笔记，不能把语义验收当成速度提升。

# ADR-0019：send 使用显式帧输入槽与恢复接收局部

- 状态：已接受
- 日期：2026-11-01

## 背景与决定

ADR-0017 的全局部帧已保存复合表达式在暂停前求出的临时值。send 只需把当前恢复操作的输入
放进独立控制槽，而不需要重建 Python 栈或增加每次恢复的对象分配。

帧布局升级为槽 0 PC、槽 1 本次 send 输入、槽 2 起原 LocalId。MIR Suspend 携可选接收局部；
恢复目标在全局部恢复后读取输入，并清除控制槽额外引用。普通语句 yield 忽略输入但同样清槽。
next / MoveNext 传 None；send 传原对象。恢复委托 ABI 不变，CIL 不新增 Python send 逻辑。

Runtime 以单独 started 标志判断首次操作，不能把 PC 数字当首次状态。新建非 None send 抛
TypeError 但不开始或关闭；重入先报 ValueError；已经关闭时任意 send 都按普通耗尽处理。
return value 的一次性消费规则不变，参数个数错误不改变生成器状态。

## 作用域与代价

HIR 保留 yield 表达式，lambda 的 body 独立扫描；嵌套 def/lambda 默认值仍在外层作用域执行。
推导式内部 yield 报 E0100，最左 iterable 的外层暂停合法。模块 / 类体不允许 yield。
复合表达式跨暂停仍全局部 spill，性能代价与 ADR-0017 一致，尚未进行存活性裁剪或速度宣称。
throw / close、yield from 与异常清理状态仍未完成，不能把 send 完成等同完整生成器协议。

当前还对调用实参内 yield、字典字面量内 yield、属性 / 下标增量赋值跨暂停报 E0100：
方法绑定、星号实参展开、哈希插入与目标保存的时序须在后续独立竖切完成，不能静默延后。
可以先把 yield 的接收值赋给局部，再进行这些操作；不把该限制冒称完整表达式兼容。

tuple / set 的星号展开含 yield 同样明确拒绝：现有展开临时列表尚需保留最终类型与集合哈希时序；普通列表星号展开不受此项限制。

# ADR-0037：受守卫短浮点算术链的中间盒消除

状态：M3.10 首个有界实现已通过真实差分及预定一次配对/JIT；接受有限默认，聚合正确性门禁已通过，不代表整个 M3.10。

## 背景与目标

M3.9 的四核心实测显示，矩阵三次 100×100 乘法仍分配约 144.67 MB，
N-Body 十万步仍分配 679,309,624 B；两者该口径 kernel 均慢于 CPython。
它们不是可用局部专项倍数掩盖的热点。生成 MIR 已有真实可定位机会：矩阵内层
三个 GetItem 后紧邻 Mul / Add.inplace；N-Body 的距离平方是连续五条 Mul / Add。

首切不按函数名识别基准，不改 Python 源码，不再加逐条运算的 C# 解释 helper。
让可证明不被观察的中间浮点值留在直接 F64 CIL 局部，为 JIT 暴露原始算术链。
矩阵链理论只省乘积的一只盒，距离平方理论省四只盒；最终结果盒仍保留。
这些是结构估计，不是已测分配或速度。

## 选择与边界

暂不做函数入口整个列表/矩阵验证：它可能提前访问实际不执行的元素，新增 O(n²)
扫描，并且无法凭入口 list 类型证明途中可变、异构或自定义索引后的每个值。
也不凭注解将整个 Dynamic 函数静态化。首切选择同块短算术 DAG：

- 仅 2–8 条连续的动态 Add/Sub/Mul；仅最后一项允许 inplace Add/Sub。
- 外部输入最多八个，均为已经求值的 Dynamic 局部；入口保存原对象引用，
  用纯 CLR 精确 double 守卫，不调用 Python isinstance、__class__ 或转换协议。
- 中间目标必须匿名、全函数唯一定义且所有读取都在当前链内。
  外部别名、身份观察、返回/存容器、后继块/循环读取均拒绝消盒。
  首切拒绝定义版本复用；链内不得重写外部输入。
- 不跨 Call、GetItem、写回、TraceSetLine、分支或其它指令；操作数原有读取
  已在链之前执行，快慢路径均不重放容器读取或用户调用。
- 任一输入不是 actual double，就按原顺序执行完整原动态链一次，保留
  __mul__/__radd__/__iadd__、NotImplemented、异常与身份；不执行再重放前缀。
- 全真分支机械 UnboxExactF64，按原次序逐条 F64 Add/Sub/Mul，最后一次 Box。
  不重结合、不主动 FMA、不改变逐操作舍入；NaN、带符号零与溢出到 inf 是正常值。
  除法、幂及其它可抛错数值操作不在本链范围。
- 无 EH、环境、cell、生成器或暂停；最多原 128 块/512 局部、16 次候选尝试，
  失败候选同样消耗预算。不通过无边界扫描换取少数机会。

新增 MIR 仅是 IsBoxedF64 / UnboxExactF64 的机械类型测试与拆箱。
独立 exact must 分析按 I64/F64 区分，写入 kill、合流取同类型交集；
I64 叶调用实验不能因 F64 也是 exact 就意外扩大。后端只生成 CLR 指令，
不判断 Python 算术或推断可省对象。

## 预先固定的验收

先 pending 差分，再结构锁实际命中与拒绝，最后测量；未命中程序的正确输出
不能证明该优化正确。覆盖 bool/int/大整数/custom 回退、首/末 guard 失败、
中间身份与跨块观察、逐次舍入、NaN/负零/inf、原异常位置和求值次数。

保留 M3.9 同 runtime 编译基线；成功/失败专项与矩阵、N-Body 原规模配对，
两 tier 各一组交错三进程×七样本，资源与 JIT 单独采集，不混入正式时间。
检查实际 CIL、JIT 指令和分配；确认没有 FMA/重结合后才接受浮点语义。
如发现具体设计缺陷，至多一轮有原因的修正配对；不为追求有利数字无限重复。
净收益不足则不默认启用。整 M3.10 收尾再一次完整正确性/性能门禁，
不在每个微型切片重复整套或将其独立提交。

## 后果

增加类型守卫和快慢 CFG、局部及代码体积；第一次失败的类型/失败位置不同
可能影响成本，必须保不利对照。只消除不可观察中间盒，不是一般逃逸分析，
不消除最终可观察 float 身份，也不是容器布局特化或 SIMD 已经完成。

## 实现证据与唯一预定配对结果

58 项 MIR 测试、1 项真实 PE 指令测试及 3 项 driver 测试已通过；
真实矩阵/N-Body MIR 确认命中，完整固定 CPython 3.12.13 差分转正后再次通过，
守卫失败保留用户 __radd__ 原始源码行。日志 `/tmp/ryupy-m3_10-f64-focused.log`、
`/tmp/ryupy-m3_10-f64-codegen.log`、`/tmp/ryupy-m3_10-f64-final-e2e.log`。

首次独立分配测量每三万轮：Mul/Add 链 1,440,000→720,000 B，
五节点距离平方 3,600,000→720,000 B；三分之一命中混合少 240,000 B。
首/末守卫失败的 bool/int/custom 各路径分配不变，结果/回调次数/身份均核验。
这是已执行产物的资源证据，不是结构估算。预定配对已终态，未为有利数字重复。


纯链默认模式 Mul/Add 耗时 -65.7%、距离平方 -69.0%，禁 tier -64.2% / -74.1%。
不利对照不隐藏：默认首 bool 失败 +32.1%（约 +36 ns/轮），首 int 失败 +24.1%
（约 +3.2 ns/轮）；禁 tier 对应 -3.4% / -3.0%。混合默认 +1.1%、禁 tier +2.3%。
因此不宣称守卫失败免费，也不保证所有动态数值程序更快。

真实矩阵原规模默认 157.556→136.033 ms（-13.7%），禁 tier -12.4%；
三次 100×100 分配约 144.67→72.67 MB，净少 72 MB。
N-Body 十万步默认 753.654→607.171 ms（-19.4%），禁 tier -16.3%；
分配 679,309,624→415,267,008 B（默认），约少 38.9%。
默认候选第一个 N-Body 进程与一次约 0.05 秒其它 Python 基线重叠，已按时间窗
登记；未删除样本/挑快值/重跑整组，不将环境限制描述为已排除。

实际采样 CIL/JIT 保持独立 mul/add/sub，无 FMA 指令。禁 tier 总代码尺寸
matmul 2442→2569 B、advance 8106→8471 B，不能称机器码更小。
advance 最后一条速度更新因候选预算保原路，不临时扩大预算追求漂亮理论值。

取舍：已证明的短链规则在两真实数值核心、两 tier 均减少时间与大量中间盒，
足以接受有限默认；非浮点失败路径默认 tier 的退化是明确代价，后续特化需要
更精确的候选/布局证据，不能因本次接受就扩到一般表达式或偷偷压掉失败路径。
原始分布、资源、源码来源、实际汇编及干扰记录由本次专项归档保存。

聚合 `make runtime && make check` 第三轮退出0：423 C#、222固定基线、196 e2e/30 ignored。
前两轮依次在同一 dataclass 用例的 MIR/CIL 旧快照失败；审阅真实新守卫与原慢路后
仅同步该两快照，25快照定向绿再完整重跑。原失败日志保留，没有改语义期望。
结果见 `/tmp/ryupy-m3_10-float-chain-checkpoint3.log`；完整性能证据见
[`float-chain/README.md`](../../tests/perf/results/m3_10/float-chain/README.md)。

# ADR-0235：源码常量与对象桥保留Python Unicode码点

- 日期：2026-11-17。
- 状态：实施中，核心语义、方法传播和实际发布分别验收。
- 接续：[ADR-0025](0025-unicode-builtins.md)、[ADR-0173](0173-declarative-cabi-signatures.md)。

## 实际失败

固定C ABI和独立原生组件的真实产品测试发现，源码`'\ud800x'`经过Ruff的Rust字符串
常量后成为替代字符。改用`chr(0xd800)`能暴露封送层原本正确的严格编码行为，但源码
字面量本身仍须修复。另一个已有差异D009是两个独立代理码点与一个补充平面码点
得到相同CLR UTF-16，导致长度、比较、字典键和桥接转换丢失区别。

## 表示与分层

syntax独占Ruff和源码token处理，保留实际代理码点转义；其余转义与f-string花括号
继续复用同一解析器。原始源码只读传入HIR，异常码点由专用HIR/MIR常量承载，
codegen发射静态工厂调用。普通可用Rust字符串的常量继续沿原`ldstr`路径。

Runtime保留CLR字符串载体。只有两个独立代理码点恰好相邻时，弱旁表登记该位置
应拆分；旁表值仅保存整数边界，未出现该元数据的程序直接越过查表。带元数据的
字符串独立分配，禁止给CLR intern池实例登记。字面量工厂复用同一常量对象，常见
全切片、空拼接、单项join和乘一等身份规则继续保留。

对象桥使用每个码点两个UTF-16单元的中性传输格式；它能无损区分独立代理项和真正
补充平面字符。原生创建、读取持有实际GIL和owned引用，身份缓存优先返回活原对象；
owner退休后重新导出仍从纯CLR码点证据恢复。快照和字符串旁表没有Host/owner强回边。

## 逐行为准入

源码普通串、隐式拼接、f-string片段/规格、文档字符串与注解分别验证。核心覆盖
len/ord、下标/切片/迭代、码点比较、hash一致性、字典键、repr、拼接/重复和严格UTF-8。
普通ASCII/BMP切片和首字符即不同的比较继续采用原有量级，避免少见表示修复拖慢
常用路径。每个新建字符串的方法都须按实际码点传播边界，完整方法生态继续独立推进。

生成字符串的C ABI负例使用原始字面量重验，并保留此前替代字符的红证；普通CIL与
provider桥分别做JIT/NativeAOT删除输入后搬迁。旧D009最小输入保留并在通过后转正。
尚未迁移的方法保留完整CPython差分pending，明确剩余行为与适用条件。

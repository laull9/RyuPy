# ADR0043：AOT作为持续性能与交付主线

状态：用户已批准方向；除已归档Linux CLI首切外，下列分阶段能力为计划。
日期：2026-11-02。

## 用户目标与当前事实

用户最新要求：AOT作为重大项目持续适配，增强AOT后性能，以代码生成适配动态性，
目标接近Nuitka级别打包。它不再只是“publish命令能跑”的一次性勾选项。
原16/20兼容前置按ADR0042暂停；不重建丢失M3.11长尾、不把历史10/20冒当前能力。

当前已验：M3.10生成CIL、静态桩、Linux x64 glibc公开CLI --aot、裁剪警告阻断、
模块/闭包/生成器/用户异常/argv/退出码及无dotnet/Python容器搬迁。见ADR0005及
[真实CLI证据](../validation/aot-driver-ci/README.md)。其它平台、完整资源打包与性能
结论尚未验收；仍依赖已披露的Linux系统库。

## 对标的是交付能力，不是声称兼容等同

2026-11-02核对[Nuitka官方手册](https://nuitka.net/user-documentation/user-manual.html)：
其区分standalone与onefile，提供包数据/文件包含配置及编译报告。我们以可搬运部署、
明确资源/依赖收集和可诊断性作为方向，不能据此声称现有Python覆盖、插件生态或性能
已与Nuitka相当；不复制其实现或承诺所有包自动可用。

## 动态性通过构建时代码生成适配

先复用已存在且真实通过的静态ldftn调用根、模块init/get/set、闭包/生成器thunk和异常
factory。只有具体裁剪/动态协议缺口证明需要，才增加有界type/module registry、构造器、
accessor和protocol-dispatch生成入口。可由编译器发CIL或生成桩，按证据选择，不预设
必须Roslyn，也不以反射发现、运行时Emit、根住全部程序集或关闭trim掩盖错误。

动态值的标签/身份/溢出升级、调用次序与guard退化保持；注解不变成额外运行时类型限制。
真正运行时未知代码/任意loader仍明确不支持，代码生成不能魔法消除开放世界问题。

## 近期执行与停止条件

先固定少量既有语义/ISA用例扩N1，再固定核心kernel及普通/退化对照做N2。
每批预声明源码、变体、样本数/预热数、运行顺序与预算；JIT默认/禁tier和AOT分别记录，
冷启动不能冒稳态，AOT也不能预设更快。CI性能为该runner观测，不泛化用户硬件。

每个候选保CIL/原生或JIT机器码、守卫命中与分配证据，真实热点才实施typed CIL、
去装箱/union/逃逸、typed容器、循环或SIMD有界优化。不得重排IEEE运算或吞身份/异常。
未达净收益的实验保默认关闭；负结果保留，不能循环调参直至出现有利数字。

小而已验证的改动及时推送main；隔离未验工作及时WIP备份。阶段计划不勾成实现，
AOT持续主线与日常交付并行，不等待“所有动态性/所有平台优化完”才发布可用增量。

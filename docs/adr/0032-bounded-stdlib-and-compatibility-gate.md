# ADR-0032：有界标准库交付与独立项目兼容性门

- 日期：2026-11-01
- 状态：已接受（用户明确批准重排；实现完成状态仍以 TODO 和实际门禁为准）

## 背景与授权

M3.7 已实现声明范围的 argparse、logging、unittest、Enum、copy、datetime、random、
string 等项目入口 API，并补齐实际项目暴露的有限语言/协议路径。原任务把标准库
交付与持续追逐项目阻断绑定，导致每个首阻断后又出现新的传递依赖，进入长尾。
第六轮最终完整矩阵仍为 4 native / 14 unsupported / 2 failed，固定分母20：
chardet 已编译但缺 enum.Flag，progress 已编译但遇到 mapping 百分号格式边界。
不能因为工程测试全绿而称项目兼容完成。

用户询问长尾进度后，明确同意以下重排：先对这两个已能编译的项目做有界收尾，
其余缺口按影响项目数与成本排序；把标准库里程碑完成与16/20兼容率拆成两个明确
阶段，再推进 JIT 优化。本决定只调整验收归属和工作排序，不授权隐藏失败或改变分母。

## 原要求保留记录

M3.7 原最后一项为：

> 验收：项目实际入口和固定上游测试通过；原生覆盖不足时继续补阻塞，不能靠减少分母达标

M3.10 原兼容要求包含：

> 冻结分母不变，至少 80% 项目原生通过预定入口与上游测试范围；若未达标，继续按失败阻塞排序实现

后者及原有结果分类、逐 API 失败原因、完整测试/文档验收条目，原文迁入 **M3.11**，
保持未完成。原要求没有通过删除分母、缩小既有项目入口或把桥接计为原生来实现。

## 决定

1. **M3.7 有界标准库交付**：保留原API清单、准确语义边界、实现路径与许可来源。
   当前新增收尾限定为已定义的字符串 mapping `%` 与真实 `enum.Flag` 子集，
   每项有 pending 基线、原生差分、只读审查与完整门禁；随后实际重跑两个项目及全矩阵。
   如果出现 bytes 正则等重大新链，记录具体失败与成本，不把该链自动加入本轮。
2. **M3.11 独立兼容性门**：固定20项目至少16项原生通过既定入口/上游范围。
   原生、桥接、带偏差、部分通过、unsupported与failed分别登记；没有满足就不勾完成。
   Phase 3 整体兼容目标继续受此门约束，不把 M3.7 标签当作80%兼容标签。
3. **M3.10 独立 JIT 性能验收**：按用户方向，将热点暴露为直接typed CIL，
   追踪类型特化、逃逸/分配与装箱消除、容器特化、循环/SIMD；保留守卫和正确回退。
   验收必须包含 CIL、JIT机器码、命中率、分配与冷/热吞吐，不只加速通用C# helper。
4. **M3.8 / M3.9 不假完成**：桥接宿主与首批优化条目继续未完成，后续按实际依赖、
   可复用性和JIT准备度评估优先级；本次决定不自动实现、跳过或勾选这些功能。

## 后果与防止范围漂移

- 标准库可形成完整工程交付，不再被单库级联需求无限延后；代价是里程碑标签必须
  明确只代表声明的API与验收，而非整套CPython标准库或固定项目80%覆盖。
- 新发现阻断进入按影响面/成本排序的兼容待办，保留原案例与准确失败分类；不得删除
  pending、降低项目预期输出、修改第三方源码或制造模块stub凑通过。
- 当前“4/20”不因重排改变。每次完整复测更新真实数字，重大新增链向用户汇报，
  不承诺两个项目完成某个首阻断就必然native。
- 用户要求完整里程碑才提交：M3.7须在上述有界工作、最终门禁、文档和独立审查齐备
  后才单次commit/tag并协调远端发布；本ADR接受不是对半成品提交的授权。

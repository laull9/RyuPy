# ADR-0035：有限纯叶调用的守卫特化

状态：配对实验与默认/显式开关聚合门禁已通过；决定默认关闭，不代表 M3.9 全部完成。

## 实际瓶颈与边界

普通可静态解析调用已经直接调用编译函数；动态别名调用经过 PIC、委托和 thunk。
现有 thunk 对准确位置参数已有快路，PIC 也复用参数槽；本实验不能宣传
“首次绕过 binder”或“消除每轮实参数组”。基线证据见
`tests/perf/results/m3_9/alias-baseline/README.md`。

本切只对普通顶层、无环境 / cell / 生成器 / EH、无默认值或可变参数的纯叶函数
预测一个目标：一至两个 Dynamic 参数、Dynamic 返回，仅参数相加与必要帧记录。
标注不是拒绝 Python 值的类型契约；不适配形状直接保留原调用。
程序级摘要和改写属于 MIR，后端不认识 Python 模板，也不生成运行时解释循环。

## 运行时守卫与回退

callee 与实参先按原顺序求值并保存，再比较实际函数身份、实际 CLR long 类型，
以及有符号加法是否溢出。真边直接有类型加法并装箱结果；假边执行完整原动态调用。
不能只回退到加法 helper：身份失配时目标可能已替换为另一函数。
布尔、浮点、大整数、用户协议、序列及整数溢出都走原调用，不重新求值实参。

快边仍执行与普通 PushFrame 共用的 CheckDepth：递归上限是可捕获的
RecursionError，不属于可忽略的内存耗尽差异。检查不压帧，和原 PushFrame
在达到限额时尚未压帧的行为一致。仅在身份、类型、无溢出守卫成功后执行，
假边由原入口检查，不能重复检查或改变异常帧。
完整 frame / tracing API 当前不支持；纯算术成功边没有 Python 回调，
故省略其临时帧不会隐藏受支持的用户观察。失败路径保原函数与回调 traceback。

## 私有身份锚点

公开 function_global 可被模块属性赋值改变，不能拿它作原函数身份的可信来源。
被选目标新增独立 Dynamic 私有锚点；后端在构造原 PyFunction 的同一个位置
用 Dup 同时保存原函数槽和锚点，而不是运行用户模块语句后再读取公开槽。
链接重映射锚点，验证器拒绝导出、MIR 写入、错误类型、缺失或槽身份混用。
模块重绑定、实参回调修改公开名字均由真实身份守卫处理。
模块属性删除是优化前已存在的缺口：旧 CLI 与候选均在 `del left.twice`
抛 AttributeError。完整原期望保留在独立 pending `leaf_identity_deletion`，
本切不扩模块删除 ABI，也不把删除行为算已通过。

锚点是强引用。它可能延长原函数及其 attrs 引用图的寿命；目标数量有限
不等于保留字节数有限。当前没有弱引用语义保证，本切如实登记此内存成本，
不称为弱缓存或无成本；若未来需要支持精确生命周期观察，应重新评估表示。

## 预算、验收与默认策略

每个调用点一个预测，每个函数最多四点，每个模块最多三十二点、八个目标。
超预算保原调用而非编译错误，不凭未命中模板的差分绿色证明特化正确。
结构测试必须锁实际改写、守卫合流及不适用形状；真实差分覆盖公开名和别名
替换、跨模块同名目标、参数求值中重绑定、原盒身份、溢出与用户回调异常。
递归边界另外验证快边和原调用行为一致。

候选完成后以相同 runtime、相同负载交错配对，记录预热与禁 tier 两组、
分配、实际 JIT 代码和守卫失败路径；单独记录分析及代码体积代价。
只有语义、净收益、审阅和聚合门禁均通过才选择默认启用；没有净收益则保原路，
不因少一层调用或少若干字节就扩大不安全候选，也不无限追逐单微基准。

## 第一组实验与一次范围收窄

宽范围候选的两组配对已归档 `tests/perf/results/m3_9/leaf-first`。
实际整数调用显著获益，但完全失败的 bool / custom / 重绑定路径出现重复退化；
不能只选择快路数字批准广泛默认。原 alias/direct 的实测分配相同，
六类守卫负载本轮没有单独分配测量，缺值不能当零。

因此仅尝试一次有根据的收窄：调用点的全部实参必须已经由编译器 must 数据流
证明为精确装箱 I64（例如 range 计数器或 len 的真实 I64 结果），而不是从注解猜测。
分析一次固定点后逐语句检查，只保存合格调用点集合；写入、未知路径、bool 合流
及回边都沿既有 kill / 交集规则。泛动态参数调用不进行此次特化。
原函数身份和溢出仍需要守卫；已知 I64 但函数已重绑定的失败路径仍须配对测量，
不能因为删去不适用候选便宣称所有回退免费。当前收窄候选仍在验证中。


## 收窄实验结论：保留原调用作为默认

收窄后原 alias(index) 负载默认快约 68–73%，但已知整数参数、函数重绑定的
失败路径仍重复退化：index 场景默认约 68.68→85.78 ns/调用、
73.17→84.79 ns/调用，禁 tier 约 40.74→49.24、44.12→47.51。
这些数值是整个循环时间除以调用次数，不是剥离循环后的纯 callee 成本。
不把失败路径的十余纳秒开销隐藏在成功路径倍数后，也不继续为一个微基准反复调参。

最终默认不运行 LeafInline；保留显式 `--experimental-leaf-inline` 供研究，
与直接累加槽实验开关独立。实验仍限定已证明精确 I64 实参，不恢复宽范围猜测。
默认不分配原函数私有锚点；实验才承担其保留对象与代码体积成本。
本决定完成的是受守卫有限特化的首批实验取舍，不是默认性能验收或全项目加速。
未知实参负载的完整 CIL 与原路径相同，表示它不再命中，不能算“守卫提速”。

真实分配对照也未发现调用分配消除：每 20000 次调用，known index 快路
950736 B、重绑定 947688 B，常量实参两种路径均 0 B；两套编译体相同。
这是复用诊断框架内的受测方法分配，不是进程零分配。实际 FullOpts index
448→611 B，constant 378→537 B，失败路径仍 CallValueFast；没有证据将回归
归咎于成倍展开的算术 PIC。完整数据归档后由同目录说明记录命令与环境。


默认无叶改写、显式叶实验与双实验组合均已由真实 driver 验证；
`/tmp/ryupy-m3_9-milestone-checkpoint3.log` 的完整 runtime/check/projects 通过。

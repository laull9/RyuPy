# ADR-0023：字典字面量求值与哈希分批

状态：已接受。

## 背景

旧字面量每求出一对key/value就SetItem，用户hash可能在后面的表达式之前执行。
固定CPython 3.12.13的dis实验显示：≤15对采用BUILD_MAP统一插入，因编译器栈预算
16–17对采用BUILD_MAP 0加逐对MAP_ADD，更多项每17项分块建表再DICT_UPDATE缓存hash合并。这是基线实现的可观察时序，不声称所有Python实现必须同样分批。

## 决定

MIR容器构建保留该15对分界：小字典先将全部key/value按源码顺序求值并装箱成临时值，再依次
SetItem；16–17对继续每对立即插入。超过17对仅放行AST纯Number/String/Bool/None字面量键，
无用户hash/eq且不可发生hash失败，直接插入保持结果与用户可观察顺序；不模拟内部临时字典。
其余动态键明确E0100，分块缓存hash合并作为独立pending，不为本切宽改存储。不更改字典推导式的逐元素插入，不顺带实现字典`**`合并。
临时值沿用生成器堆帧保存，解除字面量内yield保护诊断；用户hash/equality只能在对应插入时执行。

## 后果

小字典同时保留更多临时引用，最多30个值，生成器全局部spill成本随之增加；无加速承诺。
没有引入新ABI或改变PyDict存储。固定CPython升级时须复核分界，不以一个简单统一策略掩盖差异。
差分覆盖15/16对与18+安全标量键、key/value暂停、重复键、后表达式异常及早期不可哈希键的不同失败时机。

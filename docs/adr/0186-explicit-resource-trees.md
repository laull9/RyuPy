# ADR-0186：显式资源目录选择

## 状态
已完成有限真实应用验收：Linux CI 43296651927 与同树 macOS/Windows CI 43298130779；两入口、完整553资源和原位/搬迁运行通过。仅 Linux 另验禁网无 Python/.NET 容器；不继承旧性能数据或宣称全包兼容。

## 背景
AOT 原生打包需要部署真实包数据。要求用户逐个列出 pyfiglet 的 553 个字体文件，虽可校验，却把包维护成本转嫁给用户。自动扫描所有依赖则会把无关文件、源码或环境状态带入发布，破坏既有显式模块边界。

## 决定
保留资源请求 schema 1 与 `files`，增加每个已选模块的 `trees`：目录相对该模块实际源码父目录，`"."` 代表父目录本身；必须显式列出字面后缀。递归展开结果排序后合入相同资源目标，不扩张模块图、不自动发现包或原生依赖。

选择器须有界，拒绝不安全路径、链接与特殊文件，不能选择 Python 源码或字节码；空匹配失败，避免拼写错误产生看似成功的残缺部署。已有单文件大小、总资源大小、目标冲突与编译源码身份检查仍适用。暂存前后重查选择集合，构建期间新增或删除匹配文件必须失败，不能静默漏包。

项目 pyfiglet fixture 改用一条目录声明，但独立预期仍来自原有锁定 553 文件清单。历史 benchmark 输入与结果不改写。新声明必须走真实公开命令及完整 receipt，而非仅证明 JSON 能解析。

## 后果
这是明确声明范围内的递归选择，不是 Nuitka 等价兼容性或完整依赖闭包。大量目录可能因安全上限拒绝；用户应拆小资源范围。输出根必须位于选择树之外，否则构建生成的匹配文件或旧产物可能递归进入选择并触发集合变化拒绝；不通过静默排除输出目录改变声明语义。扫描会增加有限 IO，不宣称性能加速；后续优化必须在相同来源/冻结合同下测量。

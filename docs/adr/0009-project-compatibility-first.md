# ADR-0009：按项目兼容性安排后续阶段

- 状态：已接受；取代 ADR-0004 中的大整数排期，限定 ADR-0008 的值类型适用范围
- 日期：2026-10-31

## 背景

Phase 1 的 M1.0–M1.5 已经跑通静态子集。旧路线把异常放到 Phase 5，没有安排真实模块系统和标准库移植，却承诺接近完整的语言兼容。这样的顺序无法支持常见多文件项目。

.NET GC 与 CPython 引用计数的生命周期不同。继续承诺所有可观察行为一致，会掩盖无法复现的析构时机，也会让冷门语义占用常用能力的排期。

## 方案

### 按语言特性表补齐

继续实现高级优化、协程和元编程，最后补运行时与生态。单个特性容易展示，项目会长期受阻于导入、异常和标准库。

### 按固定项目集推进

先补动态核心、容器、普通类、异常与模块；随后支持常用高级语法并分批移植标准库。使用版本固定的项目和 API 清单验收，记录偏差与桥接依赖。代价为标准库和项目测试投入显著增加，早期性能展示减少。

## 决定

采用按项目集推进的方案，近期目标为固定纯 Python 项目集至少 80% 原生通过。M2.0 冻结至少 20 个项目，Phase 3 验收该目标；Phase 5 发布支持矩阵与交付产物。桥接结果独立计算。

Phase 2 包含大整数升级与异常映射。ADR-0004 的 Phase 1 溢出检查继续保留，后续升级排期由 Phase 5 提前到 M2.1，覆盖静态与动态 Python `int` 路径。

普通对象保留身份与共享引用。ADR-0008 的 frozen dataclass 值类型实现继续作为 Phase 1 限定实现记录；开放身份、继承和动态对象后，默认路径必须保留身份，值表示只用于证明身份不可观察的优化，或经用户显式选择的性能扩展。`frozen=True` 本身不足以证明身份不可观察。

类型标注不能独自证明运行时类型。Phase 2 默认路径支持通用调用，特化依赖证明或守卫；守卫失败返回通用路径。不得仅因标注不匹配就新增 `TypeError`。

接受 GC、即时析构和解释器内部观测的明确偏差。其它低影响差异经 ADR、测试与项目证据确认后，可以采用高性能默认实现并公开登记。影响常用计算结果的扩展由用户显式选择。未登记差异仍按缺陷处理。

## 后果

- 旧 M1.6 的 AOT 工作移到 M5.2，保持待做；不阻塞 Phase 2。
- C# 标准库重写与适配按万行级工程安排；纯 Python 源码复用和 libpython 桥接分别记录依赖、许可证与测试。
- Phase 3 建立最小 libpython 宿主，Phase 4 复用并解决以 NumPy 为首的非纯 Python 模块导入与基本调用；数值内存协议后续按需优化。
- 协程、完整 asyncio、元类、多重继承和导入钩子暂缓，项目阻塞证据决定何时重排。
- 分层规则不变。未来的模块图、异常区域、运行时 ABI 和缓存失效边界见 architecture.md §7；各里程碑实施前再冻结具体接口。

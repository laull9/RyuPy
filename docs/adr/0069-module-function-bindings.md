# ADR-0069：有本地写入证据的模块函数公开绑定

状态：有限合同与唯一CP参考已独立审核；源码已接线；首次HIR4项、ty2项、新3应用及两个原债原样CP/JIT入口通过，结构专项首次通过，第二次正常完整门禁通过，未发布。

## 实际问题与范围

ADR0068真实差分中，模块 `for values ...` 早于同名 `def values`，Ryu却在循环中读到函数。
原始CP成功源与原流已保留。原因不只是查找顺序：HIR预登记Func优先于模块变量，普通def
只设置私有预建函数的默认值，调用还可直接指向FuncId。仅交换读优先级不会在def处发布新绑定。

本切仅选择直接顶层函数名与现有ModuleVar交集，以及重复直接def名；排除任何class参与名字。
旧装饰/运行时类的同名成功与诊断保持，未选择函数原规则保持。赋值、for、import、global、
with/except等槽证据沿既有收集器，不按变量拼写或项目名字特判。

选中名字共享真实动态公开槽；每个def在默认值、注解及装饰成功后才发布本次新函数。
默认值或装饰失败保旧绑定；旧alias和旧defaults独立。函数体按调用时公开值读取全局名，
递归同样如此；callee必须先于实参副作用冻结。导出与from-import别名应与同一槽一致。

## 类型与性能取舍

公开可变函数不能仅因int等注解而保CLR强制拆箱签名，否则经动态callee调用将错误拒绝合法异型实参。
选中及既有运行时发布的顶层函数统一采用Dynamic对象参数/返回，不改注解为运行时约束。
复用现DecoratedDef会让受影响模块main整体Dynamic，并使该模块的模块槽整体装箱；不是仅一个槽的成本。
本切不改通用类型推导来掩盖此成本。未碰撞独立模块及不读取动态modulevar的数值helper应保原结构，
用HIR/MIR/CIL结构回归锁定，而不是宣称已测零性能损失。私有预建函数冷分配本切仍可能保留。

## 未纳入范围

完全无本地碰撞的单个def在定义前读取，以及只有外部模块属性写入的内部静态函数调用，仍是独立旧债。
`del name`、全exec/eval/globals、内建同名未绑定回退及全LEGB重写不扩。
涉及class的名字不借本切扩大或收紧既有成功域。边界CP正例独立保留，不计候选通过。

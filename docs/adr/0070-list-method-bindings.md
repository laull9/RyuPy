# ADR-0070：列表四个方法在副作用前统一参数绑定

状态：唯一基线复现及有限合同已独立审核，运行时三文件已接线；新14项C#及原数值列表10项首次通过，真实结构专项1项通过；三项真实CP/JIT应用首次通过；首次正常完整门禁通过，未发布。

## 真实问题与范围

在候选 bb6b59078ae8030a11d7da661d42389db8c215e6 的同源 CPython/JIT 复现中，
`list.clear(extra)`、`reverse(extra)` 和 `pop(0, 1)` 错误成功并改变原列表；
`copy(extra)` 也错误成功。保存方法、暂停恢复路径已有部分数量检查，但错误文本和
混合关键字/位置参数的检查优先级不同。这不是仅诊断文案问题。

本切仅统一 `clear`、`reverse`、`copy`、`pop`，不重写全部容器方法签名。
完整实参求值和原有展开发生在绑定前；先拒绝任何非空关键字，再检查位置数量。
前三个方法只接受零个位置参数，pop 接受零或一个。错误发生在任何索引转换、容器写入、
数值背板物化或复制之前。参数自身产生的副作用仍保留，失败不撤销参数求值。

直接方法/PIC、保存方法和暂停恢复调用共用同一个窄绑定器；接收者仍由原调用准备阶段冻结。
成功后继续原 Clear/Reverse/Copy/Pop 和 ToIndex 正文。仅新建的绑定错误准备当前帧和 context，
不以广泛 catch 包装用户实参、索引或容器正文异常。

## 成本与未纳入范围

没有新增编译器节点、运行时 ABI、调用数组或通用 EH。直接 append 等原分派保持，保存的其它
内建方法多一次列表/四名字资格检查；四方法成功路增加少量参数分支，不宣称零性能成本或已测收益。
既有精确数值列表表示与独立数值循环应由结构/专项锁定。

pop 的用户 `__index__` 支持及宽整数转索引边界仍是独立旧债，原基线两个合法/错误边界保留，
不能把整份基线宣布为修复后全部通过。其它方法的签名、通用星号展开错误帧及全容器协议不扩。

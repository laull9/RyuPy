# 原生打包成本与显式优化偏好

本门使用固定官方 binaryornot / chardet 源码及已有真实文件分类 consumer，不修改应用算法。它测量应用的公开 `build --project`，工具自身的 Rust / C# 编译单列，不算应用构建时间。

- 基线：同一个输出根连续首次与重复**完整**构建。没有清空系统或 NuGet 缓存，也不是增量构建。
- `--profiles`：`default`、`size`、`speed` 各首次/重复构建，输出根按偏好隔离，原项目配置最终恢复。
- 保留每次构建的全量输出、总 wall time、前端末标记、构建目录与交付目录字节清单。总时长减前端标记含进程/布局等开销，不能冒称精确 SDK 时间。
- 构建完成后才运行：每个独立原生产物启动/64文件混合分类各24次（4次预热、20次采样），轮换正反顺序，保持文件缓存已热。逐次完整 stdout 与 CPython 对照，stderr 必须为空。
- 隐藏应用源码、移至无关 cwd，以最小环境运行；每个产物另执行4个固定输入的无 Python/.NET、禁网、只读容器用例。
- 输入、工具和交付目录在测量后必须保持原字节。原始数据和失败输出上传 CI artifact，不提交生成 IR 或本机二进制。

`size` 只是优化偏好，不保证每个应用都更小；`speed` 不保证吞吐更快。启动含运行时初始化和应用导入，64文件分类含文件I/O，不是纯计算内核吞吐。六份产物间的差异应报告具体工作负载、机器、重复样本和交付体积，不能外推至所有 Python 应用或 Nuitka。

验收结果待实际 CI 原件核实后记录；不以脚本存在代表已验证。

# 数值插入候选负结果与host归因设计

产品候选 `d9a30620ef3729d806c462c907d2cc93c3018dc4` **禁止合入dev**。
此前源码 AOT 四轮 `insert_many` 相对固定基线持续慢约51–56%；单次插入的收益不能抵消
重复头插退化。此处保存该否决结论，不将回退直接归为噪声，也不先归因为16B槽宽。

## 固定设计

- base `86c8b97bfa4dd576d861c4b6122c91ac80125217`；candidate上述精确产品提交。
- 四轮AB、BA、BA、AB；每轮每臂独立worktree、构建及testhost进程，固定SDK10.0.403。
- 两版本注入完全相同 `InsertHostDiagnosis.cs`，不修改任何产品文件。
- 512、5000、50000 初始元素；一次头插与2000次头插；四种表示：fresh numeric PyList、
  同样构造后预先公开Items的PyList、raw List<double>、raw List<Pair16>。
- Pair16为显式顺序布局的double+object，检查实际16字节；只作CLR布局代理，不是私有
  PyNumericSlot的等价实现。raw double没有Python对象身份合同，不能直接替代产品。
- 每cell预热3次、测7次，轮换四表示顺序；每进程168测量行、72预热行，总1344测量行。
- 每cell复用同一shared double盒。构造、反射、断言、序列化均不计入操作时间；
  循环本身及单次委托调用在时间内。全量长度、值序列与适用的原盒身份oracle在计时后执行。
- 保存每操作ticks、线程分配字节、GC0/1/2差分、前后背板和容量，分配与时间分别分析。

## 必须保留的局限

这是 **host诊断，不是产品AOT复测、暖态产品承诺、跨平台验收或纯槽宽因果实验**。
自然构造后 numeric/raw 列表按CLR增长容量；预公开Items物化为Count容量，且已分配所有盒。
构造过程相同起点但最终容量/分配史不同，均记录，不能把容量及物化差异当作槽宽效应。
额外容量不足的扩容、引用写屏障、CLR复制路径、Runtime分派、泛型JIT专门化、tiering/PGO、
GC和缓存状态同时可能改变；不强制GC，构造虽排除计时仍会影响后续GC。
预热只3次，不保证各路径已达稳态；同进程跨cell存在顺序影响，轮换只是降低偏置。
单次插入耗时很短，计时和委托开销可能占明显比例；共享runner仍有噪声。
预物化/原始列表结果只能辅助归因，不能作为生产路径选择或阈值的充分依据。

raw double在计时外解包，raw pair在计时外构造；PyList仍承担真实Runtime类型检查。
每样本计时后的全量oracle会观察/物化剩余槽，JSON写出会分配并触及IO，这些虽不计入
当前操作仍影响下一cell的GC/缓存状态；原始计时不能消除该跨样本干扰。
